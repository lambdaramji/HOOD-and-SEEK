### C3 · #22 — 재실행 명령이 증명하려는 것을 증명하지 못한다

x86_64 컨테이너에서 돌려 놓고 결과를 "미완료 / 실패"로 정직하게 적은 점은 좋다. Pi4 값을 지어내지 않았다. 문제는 「실제 Pi4에서 재실행할 명령」이다. [문서]

```bash
dart compile aot-snapshot pi5_gateway/bin/hood_seek_gateway.dart -o /tmp/hood-seek-safety.aot
…
timeout 5s dart run pi5_gateway/bin/hood_seek_gateway.dart
```

- `dart compile aot-snapshot`이 만드는 건 **자립 실행 파일이 아니라 스냅샷**이다. 실행하려면 `dartaotruntime`이 따로 있어야 하는데, 목록에는 그 실행 줄이 없다.
- 다음 줄의 `dart run`은 **Dart SDK 전체**를 요구한다. ATLAS Headless에 Dart SDK를 깔아야 통과하는 절차라면, 검증하려던 명제("Yocto 이미지 재빌드 없이 바이너리만 갱신할 수 있는가", #19 ARC-001의 수용 기준)와 정반대 결론을 만든다.
- **`dart compile exe`로 자립 실행 파일을 만들고 그 파일을 Pi4에서 직접 실행해야** ARC-001이 묻는 것을 답할 수 있다.
- `journalctl -k -b … | rg` — `rg`가 ATLAS Yocto 이미지에 있다는 보장이 없다. `grep -Ei`가 안전하다. [추정] 확인 방법: Pi4에서 `command -v rg`.

절 위치도 어긋난다. 이건 조사·시험 기록이므로 `inbox/정정인/2026-09-02-*.md` 자리이고, `CLAUDE.md`가 정한 `[실측]`/`[문서]`/`[추정]` 표기도 붙지 않았다. 결정 문서 본문에 x86_64 컨테이너 로그가 73줄 들어가면, 나중에 실제 Pi4 로그가 나왔을 때 어느 쪽이 유효한지 다시 판별해야 한다.

**판정: 명령 수정 + `inbox/`로 이동 후 병합.** P-009 본문에는 "선행 확인 미완료(→ inbox 링크)" 한 줄만 남긴다.
