## 판단 필요사항

구현을 시작하기 전에 아래 항목을 결정한다. 권장안을 선택하면 추가 설계 없이 바로 구현할 수 있다.

| 항목 | 권장안 | 다른 선택지와 영향 | 결정 |
|---|---|---|---|
| 1차 시연 환경 | **Flutter Web + Chrome** | Android·macOS까지 동시에 지원하면 권한 설정과 기기별 검증 범위가 늘어난다. | 미정 |
| 인식 방식 | **마이크 버튼을 누르는 push-to-talk** | 항상 듣기·호출어 방식은 연속 인식, 개인정보와 오작동 대응이 추가로 필요하다. | 미정 |
| 제어 범위 | **후드 꺼짐·약풍·중풍·강풍만** | 인덕션 제어까지 포함하면 안전 승인과 ESP32 연동 정책이 먼저 필요하다. | 미정 |
| 음성 처리 | **`speech_to_text` 7.4.0과 장치·브라우저 인식 기능 사용** | Raspberry Pi 오프라인 Whisper는 설치, 성능 최적화와 통신 구현이 추가된다. | 미정 |
| 네트워크·개인정보 | **데모 중 Chrome 음성 서비스 사용 가능으로 합의** | Chrome은 환경에 따라 음성을 서버에서 처리할 수 있다. 완전한 오프라인이 필수라면 구현 방식을 변경해야 한다. | 미정 |
| 지원 문장 | **정해진 한국어 키워드만 허용** | 자유로운 자연어 해석에 LLM을 사용하면 지연, 비용과 오판 가능성이 늘어난다. | 미정 |
| 인식 실패 처리 | **상태를 바꾸지 않고 인식 문장과 오류 표시** | 낮은 신뢰도에서도 실행하면 오작동 위험이 커진다. | 미정 |
| 기존 버튼 | **음성 기능과 함께 유지** | 음성만 허용하면 인식 실패 시 조작할 대체 수단이 없다. | 미정 |

결정 결과는 이 표의 `결정` 열에 기록한다. 제어 범위나 오프라인 요구사항이 권장안과 달라지면 구현 전에 문서를 갱신한다.

## 목표

사용자가 Flutter 대시보드의 마이크 버튼을 누르고 짧은 한국어 명령을 말하면, 인식된 문장을 화면에 보여주고 기존 후드 풍량 상태를 변경한다.

이 단계는 음성 명령 UI와 명령 해석을 검증하는 데모다. Raspberry Pi·ESP32로 실제 제어 명령을 전송하지 않는다.

## 지원 명령

| 인식 예시 | 변경할 `_fanLevel` | 화면 상태 |
|---|---:|---|
| `후드 꺼줘`, `후드 정지` | 0 | 꺼짐 |
| `후드 약풍`, `약하게 틀어줘` | 1 | 약풍 |
| `후드 중풍` | 2 | 중풍 |
| `후드 강풍`, `세게 틀어줘` | 3 | 강풍 |

지원하지 않는 문장은 실행하지 않고 `지원하지 않는 명령입니다`를 표시한다. 명령 실행 전후에도 기존 수동 버튼은 계속 사용할 수 있어야 한다.

## 구현 방식

### 의존성

```yaml
dependencies:
  speech_to_text: ^7.4.0
```

`speech_to_text`는 장치별 음성 인식 기능을 Flutter에서 호출한다. 짧은 명령과 문장에 적합하며 Android, iOS, macOS, Web과 Windows를 지원한다. 1차 범위에서는 현재 시연 환경인 Chrome만 검증한다.

### 처리 흐름

```text
마이크 버튼 선택
→ 마이크 권한 요청 및 인식 시작
→ 한국어 음성을 텍스트로 변환
→ 공백 제거와 키워드 판별
→ 지원 명령이면 _fanLevel 변경
→ 인식 문장과 처리 결과 표시
```

음성 인식기는 앱 세션에서 한 번만 초기화한다. 사용 가능한 locale 중 `ko`로 시작하는 항목을 찾아 사용하고, 없으면 장치 기본 locale을 사용한다.

### 명령 파서

명령 파서는 음성 플러그인과 분리된 작은 순수 함수로 작성한다.

```dart
int? parseFanLevel(String input) {
  final text = input.replaceAll(RegExp(r'\s+'), '');

  if (text.contains('꺼') || text.contains('정지')) return 0;
  if (text.contains('약풍') || text.contains('약하게')) return 1;
  if (text.contains('중풍')) return 2;
  if (text.contains('강풍') || text.contains('세게')) return 3;

  return null;
}
```

최종 인식 결과에 대해서만 파서를 실행한다. 부분 인식 결과는 사용자에게 현재 듣고 있는 문장으로만 보여준다.

## UI 변경 범위

기존 후드 자동 제어 카드 안에 다음 요소만 추가한다.

- 마이크 시작·중지 버튼
- `듣는 중`, `인식 준비 안 됨`, `마이크 권한 필요` 상태
- 마지막 인식 문장
- `강풍으로 변경했습니다` 또는 실패 메시지

새 화면이나 별도 내비게이션은 만들지 않는다.

## 안전 경계

- 음성 명령으로 인덕션 안전 잠금을 해제하지 않는다.
- 음성 인식 실패나 미지원 문장에서는 현재 상태를 유지한다.
- 실제 장치 연결 이후에도 Flutter는 요청만 보내며 최종 허용·차단은 ESP32 안전 정책을 따른다.
- 마이크가 활성화된 동안에는 아이콘과 문구로 녹음 상태를 명확히 표시한다.
- 음성 인식이 불가능해도 기존 수동 버튼은 항상 동작해야 한다.

## 검증 계획

### 자동 검사

- `parseFanLevel`이 지원 문장을 올바른 단계로 변환한다.
- 미지원 문장과 빈 문자열은 `null`을 반환한다.
- 인식 실패 시 기존 풍량이 유지된다.
- 음성 결과 적용 후 선택된 ChoiceChip과 우측 상태 문구가 함께 바뀐다.
- `flutter format`, `flutter analyze`, `flutter test`가 통과한다.

### Chrome 실물 검사

1. `flutter run -d chrome`으로 실행한다.
2. 마이크 버튼을 누르고 브라우저 권한을 허용한다.
3. 네 단계 명령을 각 5회 말한다.
4. 인식 문장, 선택 표시와 우측 풍량 문구가 일치하는지 기록한다.
5. 주변 소음이 있는 상태에서 같은 검사를 반복한다.
6. 지원하지 않는 문장에서 풍량이 바뀌지 않는지 확인한다.

임시 통과 기준은 조용한 환경에서 명령별 5회 중 4회 이상 성공, 오명령 실행 0회다. 최종 기준은 사용자가 판단 필요사항과 함께 확정한다.

## 후속 확장 조건

다음 요구가 실제로 확정될 때만 Raspberry Pi 오프라인 음성 인식을 검토한다.

- 인터넷이 끊겨도 반드시 음성 인식이 동작해야 한다.
- Flutter를 실행하지 않은 상태에서도 주방 장치가 음성을 받아야 한다.
- 음성 데이터가 외부 서비스로 전송되면 안 된다.
- 항상 듣기 또는 호출어 기능이 필요하다.

이 경우 `whisper.cpp`의 tiny/base 모델을 Raspberry Pi에서 실행하고, 인식된 제한 명령만 Flutter와 ESP32 통신 계층으로 전달하는 별도 검증이 필요하다.
