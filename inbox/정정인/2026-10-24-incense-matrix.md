## 요약

1. **팬 바람만으로 PM2.5는 거의 안 흔들리지만 `tsize`는 팬 1단부터 연기 없이 0.49 아래로 내려간다.** → [A1](#시험-기록)
2. **28 cm·팬 0~1에서는 인센스 1개부터 원값이 약 33,000~39,000에서 더 오르지 않는다.** 1개(B1b)와 3개(B2)는 어떤 채널로도 구분되지 않음 → [B1b·B2](#시험-기록)
3. **팬 효과는 0 ≈ 1 ≫ 2 ≈ 3.** 팬 2단부터 놓은 동안 중앙값이 약 1/20 → [C1b·C2·C3](#시험-기록)
4. **팬 2·3단에서 포화 아닌 인센스 연기의 `tsize`는 대부분 0.49 이상**(C2 98 %, C3 80 %, D1 69 %, E1 84 %). [hardware-facts.md](../../docs/hardware-facts.md) 「1,000 초과 구간 연기 0.41~0.44」와 다름 → [이전 문서 수정](#이전-문서-수정-필요-사항)
5. **[추정] 연기 경로만 오프라인 재생하면 감지는 2~8 s지만, 팬 2·3단에서 연기가 계속 나는 중 danger가 2~6번 풀린다.** 원인 대부분은 4번(비포화·`tsize ≥ 0.49` → `small=false`) → [남은 문제](#남은-문제-추정과-확인-방법)
6. **[실측] Core를 켠 D1(`D1core_1024`)에서는 hazard가 놓기 3 s 전부터 치운 뒤 20 s까지 계속 danger였다.** 불씨가 MLX 시야에 들어와 `TEMP_ABS`(max 96.4 °C)·`TEMP_DANGER`가 내내 걸렸기 때문. 그동안 `SMOKE` reason은 놓은 동안 7번 빠졌다 돌아왔고, 가장 길게 빠진 구간은 47.5 s → [D1core](#core를-켠-d1-d1core_1024-실측)
7. **정정: 배포본 `mlx_stream`의 `delta` 열은 `p95 − median`이다.** Core `T_metric`(`max − median`)으로 다시 계산하면 3개 이상 회차는 놓은 동안 대부분 `P_T_danger`(30.4) 이상 → [이전 문서 수정](#이전-문서-수정-필요-사항)
8. **[실측] 이전 제품은 비포화 진한 구간 `tsize`가 0.42 안팎, HEM은 0.58 안팎.** 9월 「연기 0.41~0.44」는 이전 제품 값 → [P1·P2](#이전-제품-비교-p1p2-실측)
9. **[실측] T3: 팬을 돌려도 손난로 네 단계 metric은 겹치지 않는다.** 45/50/55/65 °C = 16.00 / 20.86 / 24.01 / 31.30, 범위 사이 간격 4.26 / 2.40 / 6.70. Q2(10/22, 팬 없음)보다 0.18~1.65 낮음. 65 °C 최저값과 `P_T_danger`(30.4) 사이 0.66, 55→65 전환 뒤는 0.31 → [T3](#t3-손난로--팬-실측)
10. **[실측] 맨 불씨는 거리 50 cm에서도 MLX에 잡힌다(max − median 최대 37.9).** 호일 터널(약 12 cm)로 가리면 놓은 동안 최대 5.0~10.2로 `P_T_caution`(13.4) 아래 → [D 거리](#d-거리-인센스-1개-실측), [호일 시험](#호일-시험-foiltest_1024-실측)
11. **[실측] 호일을 쓴 1개 기준, 팬 3이 연기를 줄이는 자리는 28·37 cm, 45 cm(박스 옆면)에서는 오히려 늘었다.** 37 cm 팬 3이 가장 적음(포화 9 %, 중앙 210). 다만 37 cm 팬 3도 놓은 동안 77 %가 기준+50 이상 → [D 거리](#d-거리-인센스-1개-실측)
12. **[실측] 75·100 cm는 시연 박스 밖이라 연기가 박스 안으로 들어가지 않아 측정에서 뺐다**(정인 관찰, PM 구두 공유) → [D 거리](#d-거리-인센스-1개-실측)

### 조건 [실측] 10/24 13:25~15:05(Mac 시각), Pi 4

| 항목 | 값 |
|---|---|
| Core | `systemctl stop hoodseek-safety-core` 상태. `smoke_log`는 Core가 돌면 시작을 거부 |
| 기록 | `tools/smoke_log.c` 한 프로세스가 같은 `CLOCK_REALTIME`으로 SPS30(1 Hz, 0x0300 10개 float 원값 + 0xD206 상태 레지스터)·팬 UART tx/rx·이벤트를 찍고, MLX는 `/data/mlx/mlx_stream 8080 2 <csv>`(서브페이지 2 Hz = 전체 프레임 1 Hz)를 자식으로 띄워 epoch를 붙임 |
| 팬 | 로거가 1 s마다 `FAN n` 재전송. 모든 회차 tx 수 = `ACK` 수, `FAILSAFE` 0 (`meta.txt` `fan_ack`·`fan_failsafe_lines`) |
| 배치 | 불씨 끝 → SPS30 흡입구 직선(대각선) 약 28 cm(10/22 Q3와 같은 목표), 같은 받침에 세워 고정. 박스는 테이블 끝으로 옮긴 뒤. 배치 사진: **미첨부**(아래 「미확인 사항」) |
| 인센스 | **HEM 골드 에디션 스틱 인센스 100p**, 매 회차 새것. 여러 개는 묶어서 한 받침 |
| 시계 | Pi 4 시계가 실제보다 약 23일 늦음. `meta.txt` `mac_epoch_at_launch`(Mac `date +%s`)·`pi_minus_mac_s`가 기준점 |

- **이전 제품과 비교 금지.** 10/24 오전 예비 3회(`prelim/`), 10/23, 9/26, 10/22 Q3는 이전 제품(이름 미확인)이고 거리도 다름. 오전 예비 팬 0·1개는 놓은 동안 중앙값 1,096, B1b는 27,145 — 제품과 거리 차이가 섞여 있음
- **점화 시각은 참고용.** 점화 후 30 s를 다 채우지 못한 회차가 있고 `ev 점화`를 늦게 친 경우도 있음(정인). 이벤트상 점화 → 놓음: B1b 20 s, B2 31 s, C1b 20 s, C2 28 s, C3 28 s, D1 4 s, E1 4 s. 분석은 전부 「놓음」 기준
- **무효 회차(파일은 남김):** `B1_1024` 스틱 고정 안 됨 → `B1b_1024` 재측정. `C1_1024` 놓고 약 60 s 뒤 인센스가 꺼짐(PM2.5 원값 +60 s 10,845 → +65 s 3,276), 꺼진 뒤 `ev 치움` → `C1b_1024` 재측정

## 재현 방법

```bash
# 빌드 (Mac, Docker) — tools/smoke_log.c 머리말과 같음
docker run --rm --platform linux/arm64 -v "$PWD":/w -w /w alpine:3.20 \
  sh -c 'apk add --no-cache gcc musl-dev linux-headers >/dev/null && gcc -O2 -static -Wall -Wextra -o smoke_log smoke_log.c'
./smoke_log --selftest   # (arm64 컨테이너 안) selftest OK
scp smoke_log ev root@$PI4:/data/mlx/

# 한 회차 (창 1) — Core는 먼저 멈춤
ssh root@$PI4 'systemctl stop hoodseek-safety-core'
ssh -t root@$PI4 "/data/mlx/smoke_log /data/mlx/runs/C3_1024 900 3 $(date +%s)"
# 이벤트 (창 2)
ssh root@$PI4 '/data/mlx/ev 놓음'      # ev 점화 / ev 치움 / ev fan 3 / ev 환기

# 가져오기와 요약 (이 폴더에서)

python3 tools/summarize.py B1b_1024 B2_1024 C1b_1024 C2_1024 C3_1024 D1_1024 E1_1024
python3 tools/replay110.py B1b_1024 B2_1024 C1b_1024 C2_1024 C3_1024 D1_1024 E1_1024 A1_1024

# 저녁 회차
```
