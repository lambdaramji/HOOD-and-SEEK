## 0. 준비 (약 5분)

### 0-1. I2C 3장치 동시 응답

```bash
ssh root@<Pi4 IP>
i2cdetect -y 1          # 또는  /data/mlx/i2c_probe
```

| 주소 | 장치 | 응답 |
|---|---|---|
| `0x33` | MLX90640 | ☐ |
| `0x68` | DS3231 | ☐ |
| `0x69` | SPS30 | ☐ |

> `0x69`가 안 뜨면 **SEL 핀이 GND에 연결되지 않아 UART 모드**입니다. 멘토 확인 요청으로 남아 있던 항목이 여기서 판명됩니다.

### 0-2. 배치를 숫자로 고정

보정계수가 배치에 종속되므로, **이 표를 채우지 않으면 오늘 측정도 다음에 또 무효가 됩니다.**

| 항목 | 값 |
|---|---|
| 열화상 ↔ 열원 거리 | ___ cm |
| 열화상 설치 각도 | ___ ° |
| SPS30 ↔ 연기원 거리 | ___ cm |
| SPS30 방향 (박스 개구부 기준) | ___ |
| 박스 개구부 크기 | ___ cm |
| 사진 | ☐ 찍어서 첨부 |

#### 시연 박스 구조 [문서: 담당자 스케치, 2026-09-26]

| 항목 | 값 |
|---|---|
| 크기 | 가로 50 × 높이 40 × 깊이 30 cm |
| 개방면 | **앞면 전체 뚫림** (50 × 40) |
| 벽 | 좌·우·윗면 투명, 뒷면 불투명 (오른쪽 아래 구멍 1개) |
| 천장 중앙 (아래를 향함) | 카메라, 열화상 카메라, SPS30 |
| 바닥 앞쪽 가운데 | 인덕션 디스플레이 (디스플레이 1) |
| 센서 ↔ 바닥 | 약 40 cm (자극 물체 높이만큼 짧아짐) |

- 핫팩·향·가습기를 모두 **같은 「냄비 자리」** 에 두어야 세 측정이 같은 경로로 비교됨 (제안). 이번 핫팩 위치(디스플레이 옆 바닥)를 냄비 자리로 고정하면 열화상 안 C(디스플레이 영역 제외)와도 맞음.

## A. 열화상 임계값 재측정

```bash
# 영상 + CSV 동시 기록. 기존 파일이 있으면 거부합니다(덮어쓰기 사고 방지)
/data/mlx/mlx_stream 8080 1 /data/mlx/box_hotpack.csv
# 브라우저: http://<Pi4 IP>:8080
```

CSV 열: `sec,max,p95,median,delta,hot_px,rise_c_per_s,ta,drop`

### A-1. 단계별 측정

각 단계 **90초 이상** 유지. `delta`가 주력 지표입니다.

> ⚠️ **배포된 `mlx_stream`의 `delta`는 `p95 − median`입니다** (`max − median` 아님) [실측 2026-09-26]. `/data/mlx/box_hotpack.csv` 첫 행 `2.0,39.10,34.33,28.10,6.22,...` 에서 `34.33 − 28.10 = 6.23`. 09-02 `hotpack.csv`의 `delta` 열도 같은 정의입니다(`27.59 − 26.12 = 1.47`). 다만 **09-02 임계값 8/16/22는 이 열이 아니라 `max − median`으로 산출**됐습니다 — 09-02 파일에서 max≈34/41/49 행의 `max − median`이 `8.23 / 14.98 / 22.35`, `delta` 열은 `1.45 / 1.51 / 2.20`. 따라서 임계값 비교는 CSV의 `max`·`median` 열로 **`max − median`을 직접 계산**해서 합니다. 저장소 `mlx_bundle.sh`(v3, 11열, `delta = max − median`)는 Pi4에 배포된 바이너리(9열)와 다릅니다.

**기록은 끊지 않고, 단계마다 「안정화 대기 → 측정 구간」으로 나눕니다.** 핫팩은 설정을 바꿔도 표면 온도가 올라가는 데 수 분이 걸리므로, 바꾼 직후 값을 쓰면 단계끼리 겹칩니다(지난 측정의 55도·60도 역전이 이 경우로 추정). `mlx_stream`은 한 파일에 계속 쓰게 두고, 아래 표에 **CSV의 `sec` 값**을 적어 나중에 구간을 잘라냅니다.

```bash
# 두 번째 SSH 창에서 실시간 확인 (파일을 읽기만 하므로 mlx_stream과 충돌 없음)
/data/mlx/mlx_watch.sh /data/mlx/box_hotpack.csv
#   264초  max  45.2  배경  28.4  delta   8.5   74 px  30초변동  0.1  안정 ✓
```
경과 초와 안정 여부(30초 변동폭 ≤ 0.6°C)를 자동으로 표시합니다. 원본: [`mlx_watch.sh`](mlx_watch.sh). Pi4 busybox에서 합성 데이터로 동작 확인 [실측 2026-09-26].

| 설정 | 바꾼 `sec` | 안정된 `sec` | 끝 `sec` |
|---|---|---|---|
| OFF (기준) | 0 | 0 | |
| 45도 | | | |
| 50도 | | | |
| 55도 | | | |
| 60도 | | | |
| 65도 | | | |

- **안정 판정 (제안)**: `max`가 30초 동안 ±0.3°C 안에서만 움직이면 안정. 그때부터 **60~90초**가 측정 구간.
- 온도는 **낮은 쪽에서 높은 쪽으로만** 올립니다. 식는 데 훨씬 오래 걸립니다.
- 전환 구간은 버리는 데이터가 아닙니다. `rise_c_per_s`(상승 속도)를 보는 데 씁니다 — 화재 급상승 판정(`TH_RISE`)의 비교 기준.

|---|---|---|---|---|
| OFF | | | | |
| 45도 | | | | |

- **09-02 임계값과의 대조**: 경계 16은 구간 1(최대 14.34)과 2(최소 16.82) 사이, 경계 22는 구간 3(최대 21.74)과 4(최소 24.36) 사이에 있어 **새 배치에서도 두 경계가 구간을 깨끗이 가름**. 이 경계를 그대로 쓰면 구간 1 = 관심, 2·3 = 주의, 4·5 = 경고. **경계 8은 검증 불가** — OFF 기준 구간이 없음(기록 시작 시 이미 `max 39.10`, 상승 중).

- 정황: 두 공백 모두 **PM2.5가 1,000을 넘은 직후** 시작(`83.7s 1057.9`, `127.5s 1785.7`). 가습기 회차(`box_mist_1.csv`, 배선을 만지지 않음)에서도 공백 3곳이 **모두 PM2.5 > 1,000 직후**(`92.6s 1004.1 → 4.0초`, `99.6s 1864.1 → 6.9초`, `128.5s 1717.0 → 4.0초`) → ②(사양 범위 밖 고농도) 쪽에 무게가 더 실림 [추정].
- 확인 방법: (a) 향을 30cm 이상 두고 PM2.5 1,000 이하로 재측정 — 공백이 없으면 ② (b) 향 없이 로깅하며 SPS30 배선만 살짝 흔들기 — 공백이 생기면 ①.

## C. 임계값을 정하는 방법 (숫자를 선으로 바꾸는 절차)

A·B는 **데이터를 모으는** 절차입니다. 모은 CSV에서 임계값을 뽑는 방법은 아래입니다. 한 번 측정한 최대값을 그대로 쓰면 안 됩니다.

### C-1. 원칙

임계값은 **고르는 값이 아니라 두 분포를 가르는 선**입니다. 그래서 반드시 두 쪽을 다 재야 합니다.

| 필요한 것 | 왜 |
|---|---|
| **정상 분포** (아무 일 없을 때 5분 이상) | 오탐 기준선. 이게 없으면 임계값이 너무 낮은지 알 수 없음 |
| **사건 분포** (각 조건 **3회 반복**) | 1회는 우연. 재현되는지 확인 |
| 두 분포 사이 **간격** | 겹치면 그 지표는 단독으로 쓸 수 없음 |

### C-2. 절차

1. **정상 구간 통계** — 평균 μ, 표준편차 σ, 최소·최대
2. **사건 구간 통계** — 같은 항목
3. **분리도 확인**
   ```
   분리도 = (사건 최소 − 정상 최대) / 정상 σ
   ```
   | 분리도 | 판정 |
   |---|---|
   | > 3 | 안전하게 쓸 수 있음 |
   | 0 ~ 3 | 쓸 수는 있으나 여유 없음. 디바운스 필수 |
   | ≤ 0 (겹침) | **단독 지표로 쓰지 않음.** 다른 지표와 AND 조합하거나 폐기 |
4. **선 긋기** — 겹치지 않으면 두 값의 중간. 안전 쪽(오탐보다 미탐이 위험)이면 정상 쪽으로 붙임
   ```
   임계값 = 정상 최대 + (사건 최소 − 정상 최대) × 0.3
   ```
5. **히스테리시스** — 켜는 선과 끄는 선을 벌립니다. 경계에서 상태가 깜빡이는 것을 막습니다
   ```
   예) 경보 진입 fine > 0.90,  해제 fine < 0.85
   ```
6. **디바운스** — **연속 N회** 충족해야 판정. 1프레임 튐으로 팬이 3단이 되면 안 됩니다. 권장 3회 (초당 1행이면 3초)
7. **기록** — 임계값마다 ① 근거 CSV 파일명 ② 정상 최대 ③ 사건 최소 ④ 분리도 ⑤ 히스테리시스·디바운스 값

### C-3. 계산 명령 (Mac에서, CSV 받은 뒤)

```bash
python3 - <<'EOF'
import csv, statistics as st
F = "incense.csv"          # 또는 box_hotpack.csv
COL = "fine_pc05_pc10"     # 또는 delta, hot_px
NORMAL = (0, 20)           # 정상 구간 sec 범위
EVENT  = (50, 80)          # 사건 구간 sec 범위

rows = list(csv.DictReader(open(F)))
pick = lambda a, b: [float(r[COL]) for r in rows if a <= float(r["sec"]) < b]
n, e = pick(*NORMAL), pick(*EVENT)
for name, v in (("정상", n), ("사건", e)):
    print(f"{name}: n={len(v)} 평균={st.mean(v):.4f} σ={st.pstdev(v):.4f} "
          f"최소={min(v):.4f} 최대={max(v):.4f}")
sep = (min(e) - max(n)) / (st.pstdev(n) or 1e-9)
print(f"분리도 = {sep:.2f}")
print(f"제안 임계값 = {max(n) + (min(e) - max(n)) * 0.3:.4f}")
EOF
```

> `fine`처럼 **작을수록 정상이 아니라 클수록 사건**인 지표는 위 식 그대로, `tsize`·`coarse`처럼 **작아야 사건**인 지표는 최소·최대를 뒤집어서 계산합니다.

### C-4. 열화상에서 주의할 점

- **절대온도 보정식보다 ΔT(= `max − median`)를 우선합니다.** ΔT는 배경 대비값이라 방사율·거리 오차에 덜 민감하고, 보정식 없이도 단계를 나눌 수 있습니다. 보정식은 화면 표시용으로만 씁니다.
- 보정식을 다시 만들려면 **기준 온도계**가 필요합니다. 없으면 A-3은 건너뛰고 ΔT만 확정합니다 [추정 — 확인 방법: 주방 온도계 또는 얼음물 0°C·끓는물 100°C 2점 기준].
- `hot_px`는 **사람 vs 열원 구분 전용**입니다. 온도 단계 판정에 섞지 않습니다.

### C-5. 코드에 반영하기 전에

측정값과 현재 코드가 **어긋나 있습니다.** 임계값이 확정되면 이 불일치를 먼저 해소해야 합니다.

| 항목 | 문서 (실측 기반) | 코드 | 조치 |
|---|---|---|---|
| 온도 단계 | 34 / 41 / 49°C | `SafetyPolicy` 55 / 70 / 90°C [문서: `packages/hood_seek_protocol/lib/hood_seek_protocol.dart`] | **합의 필요** — 어느 쪽이 맞는지 |
| 단계 이름 | 정상 / 관심 / 주의 / 경고 | `enum SafetyLevel { normal, caution, warning, danger, offline }` — 「관심」 없음 | 문서 용어를 코드에 맞추거나 enum 추가 |
| `delta`·`hot_px`·`tsize`·`coarse`·`fine` | 판정에 사용 | `contracts/sensor-snapshot.schema.json`에 **필드 없음** | 계약 개정 + `schema_version` 상향 |
