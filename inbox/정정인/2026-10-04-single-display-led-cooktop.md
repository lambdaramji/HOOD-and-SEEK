## 1. 주최측 답변 [문서]

### 듀얼 디스플레이

> **질문**: RPi5 Video Profile 환경에서 HDMI 2개 포트에 각각 디스플레이를 연결할 때, Flutter 앱 2개를 서로 다른 디스플레이에 개별 지정하여 출력하는 것이 가능한지
>
> **답변**: Dual display는 지원하지 않습니다.(webOS와 다름)

→ 디스플레이 1(인덕션 화면)·디스플레이 2(사용자 UI) 동시 사용 계획은 불가.

### USB 시리얼 드라이버 · CH340

> **질문**: ATLAS 커널(26.06.0-246)에 기본 포함된 USB-Serial 드라이버 목록, `PeripheralManager1.UART`의 `UART_ttyUSB0`가 특정 어댑터를 전제로 하는지, CH340 드라이버 추가 제공 가능 여부
>
> **답변**: 플래싱된 이미지에는 따로 USB Serial 드라이버가 설치되어 있지 않습니다. 배포된 Connman setting guide 내용을 확인하시고 개발 환경에 맞는 드라이버 설치 후 연결을 진행하시면 됩니다.

해석:

- ConnMan 설정 가이드의 드라이버 설치 절은 **USB-UART 모듈을 PC에 연결해 Pi 콘솔에 접속하는 경우의 PC 쪽 드라이버**입니다 [문서: dev-docs `12-wifi-connman-guide`, PC 터미널 설정 절]. 우리 질문(ESP32를 **Pi에** 꽂는 경우)에는 해당하지 않습니다.
- 「드라이버가 설치되어 있지 않다」는 실측과 다릅니다. Pi4·Pi5 커널에 `cp210x`, `ftdi_sio`, `pl2303`, `cdc-acm`은 내장, `ch341`만 없습니다 [실측 2026-09-26, [배선 가이드 §2-C](2026-09-25-wiring-guide.md)]. 「CH340 같은 추가 드라이버는 없다」는 뜻으로 해석합니다.
- `UART_ttyUSB0`의 어댑터 전제 여부는 답변에 없습니다.
- Pi에 드라이버를 넣으려면 이미지 수정 또는 자체 빌드 커널 모듈이 필요해 **SD 이미지 수정 금지 규칙에 걸립니다.** → Pi와 **USB로** 연결한다면 CH340 지원은 기대하지 않고 CP2102 보드를 씁니다. 설계서 v0.1 D-17처럼 **GPIO UART로** 연결하면 USB는 PC에서 펌웨어를 구울 때만 쓰므로 CH340 보드도 사용 가능합니다.

---

### ESP32 보유·주문 현황 (2026-10-19)

이 문서 초판(10-04)에 「CP2102 보드 2개 주문 — 결정」으로 적었으나, **결정한 것은 2대 구성 방향이며 실제 주문은 하지 않았습니다.** 현재 보유는 **CH340 ESP32 1대**(팬 펌웨어 기록됨)입니다.

| D-17 (PM 재결정 중, Q-19) | 필요한 보드 | 추가 주문 |
|---|---|---|
| **GPIO UART 유지** (설계서 v0.1) | 칩 무관 2대 — 현 CH340 보드 사용 가능 | **1대** |
| USB로 변경 | **CP2102** 2대 — 현 CH340 보드는 Pi에서 `ttyUSB` 미생성 | **2대** |

- 2대로 나누는 이유: 팬 ESP32는 Pi가 멈춰도 팬을 3단으로 돌리는 마지막 안전장치라, LED 쿡탑 코드·전원 변동과 분리해 각자 독립 fail-safe(팬 3단 / 쿡탑 OFF, 설계서 D-21)를 갖게 함.
- 근거 실측: [#44 댓글 (2026-10-19)](https://github.com/lambdaramji/HOOD-SEEK/issues/44#issuecomment-6260197170) — Pi 4 `cp210x` 내장, CH340 `ttyUSB` 미생성, `/dev/serial/by-id` 없음, uart3·uart5 → `/dev/ttyAMA3`·`/dev/ttyAMA5`.
- 아래 3절 「Pi5와 연결 방식」의 Wi-Fi MQTT·USB 안은 10-04 기준입니다. 현재 기준은 설계서 v0.1 §4(Pi 4 GPIO UART, MQTT 폐기 D-11)입니다.

## 2. 시연 구성 변경

| | 이전 계획 | 새 구성 |
|---|---|---|
| 박스 바닥 (인덕션 자리) | 디스플레이 1 (7", 마우스만) | **검은 반투명 아크릴 + 아래 LED 매트릭스** |
| 사용자 UI | 디스플레이 2 (15.8", 터치) | 디스플레이 2 — **UI + 가상 인덕션 상태 패널** |
| ESP32 | 1개 (팬) | **2개** (팬 / 쿡탑) |

10-04 기준 그림입니다. 현재 연결은 설계서 v0.1 §1(ESP32 2대 모두 Pi 4 GPIO UART)을 따릅니다.

```text
Pi5 ──HDMI──▶ 터치 디스플레이 (UI + 가상 인덕션 상태)
 │
 ├─USB──▶ ESP32 #1 ──GPIO26──▶ IRLZ44N ──▶ 팬        ← 변경 없음, fail-safe 전용
 │
 └─MQTT(LAN)──▶ ESP32 #2 ──GPIO──▶ WS2812B 16×16    ← 쿡탑 표시 전용
```

- 쿡탑 ESP32를 분리하는 이유: 팬 ESP32는 Pi5가 죽어도 팬을 3단으로 돌리는 마지막 방어선이며, 시리얼 명령도 `FAN 0..3` allowlist만 받습니다 [문서: `firmware/esp32_fan_controller/src/main.cpp`]. 표시 기능을 섞으면 이 단순함이 깨집니다.
- 디스플레이 2(15.8")가 박스(50 × 40 × 30 cm)에 비해 큰 문제는 남습니다. 박스 앞 바깥에 조작 패널로 두는 배치를 (제안)합니다.

## 3. LED 쿡탑

### 부품 (결정)

WS2812B 16×16 유연 매트릭스 — 쿠팡 상품 `8866157573`. 판매 페이지 표기 [문서]:

| 항목 | 값 |
|---|---|
| 픽셀 | 16 × 16 = 256, WS2812B (SMD 5050 RGB) |
| 전압 | DC 5V |
| 크기 | 사양표 「약 150 × 150 mm」, 치수 그림 160 × 160 mm — 도착 후 실측 |
| 형태 | 유연 FPCB |
| 선 | 입력 3핀 암(DIN·5V·GND), 출력 3핀 수(DOUT·5V·GND), 보조 전원선(5V·GND) |
| 데이터 배선 | **지그재그(serpentine)** — 줄마다 방향이 바뀜 |

### 구조

```text
━━━━━━━━━━━━━━━━━━━━━━━━  박스 바닥 = 검은 반투명 아크릴 (위에 흰 선 화구 테두리)
░░░░░░░░░░░░░░░░░░░░░░░░  흰 종이 / 트레싱지 (점을 퍼뜨림)
     ↕ 5~10 mm 띄움
▦▦▦▦▦ WS2812B 16×16 ▦▦▦▦▦  두꺼운 종이·얇은 판에 양면테이프로 평평하게 고정
```

- 검은 반투명 아크릴이라 꺼지면 보이지 않고 켜질 때만 비침 → 별도 덮개 불필요.
- 흰 선 화구 테두리(흰 시트지 또는 흰 페인트 마커)로 실제 인덕션 상판처럼 보이게 함.
- 박스를 2 cm 정도 띄워 바닥 아래 공간 확보.
- 아크릴 구석에 「가상 인덕션 (시연용)」 표기 — 가상 상태를 실제 장치 제어처럼 표현하지 않는 원칙 [문서: `CLAUDE.md` 안전 불변식].

### 표시 규칙 (제안)

| 상태 | 표시 |
|---|---|
| 꺼짐 | 전부 소등 |
| 1 ~ N단 | 동심원 링이 안쪽부터 바깥으로 퍼짐, 색 주황 → 빨강, 가운데 단계 숫자 |
| 잠금 | 링 소등, 가운데 「L」 또는 자물쇠 |
| 단계 변경 | 링이 퍼지는 짧은 애니메이션 |

단계 수는 코드 상수 하나로 정하므로 **부품 구매와 무관**합니다.

### 배선 (결정)

| 선 | 연결 |
|---|---|
| 입력 3핀 DIN | 330 Ω 저항 → ESP32 GPIO |
| 입력 3핀 GND | ESP32 GND (어댑터 GND와 공통) |
| 보조 전원선 5V·GND | **5V 3A 어댑터에 직접** (DC 잭 단자 어댑터 사용), 1000 µF 커패시터를 5V–GND 사이에 |
| 출력 3핀 | 사용 안 함 |

- 전원을 ESP32 5V 핀으로 주지 않습니다 (256 LED).
- 코드에서 **최대 전류 1.5 A 제한**, 빨강·주황 위주. 검은 아크릴이 빛을 먹으므로 밝기는 실제로 대보고 정합니다.
- 3.3V 데이터를 먼저 직결로 시험하고, 색 깨짐·깜박임이 있으면 레벨 변환을 넣습니다. 부품함의 4CH 로직 레벨 컨버터는 WS2812 신호 속도에서 불안정할 수 있습니다 [추정 — 확인 방법: 직결·컨버터 각각 연결해 색 오류 비교].

### Pi5와 연결 방식 (제안)

| 방식 | 장점 | 조건 |
|---|---|---|
| **Wi-Fi로 MQTT 직접 구독** ★ | USB·드라이버 불필요, Pi5 코드 변경 없음 (상태는 이미 발행 중) | 공유기 Wi-Fi 필요. 설계도 ②의 「Wi-Fi OFF」 구성이면 불가 |
| USB 시리얼 (CP2102) | 네트워크 무관 | Pi5 gateway에 쿡탑 명령 송신 추가 |

인터넷은 어느 쪽도 필요 없습니다. MQTT는 공유기 안에서만 오갑니다.

## 4. 인덕션 단계 조절 — 현재 시스템에 없음 · 합의 필요

음성으로 「인덕션 켜」「화력 올려」「화력 내려」, 터치로 단계 조절을 시연하려면 아래가 필요합니다. 현재는 [문서]:

- 음성 해석은 팬만 — `parseFanVoiceCommand` (`packages/hood_seek_protocol/lib/hood_seek_protocol.dart:583`)
- 명령은 `FanCommand`만 (`:431`)
- 상태에 인덕션은 잠금 여부 `induction_locked`만, **단계 필드 없음** (`:396`, `:425`)
- 음성·Flutter는 잠금을 직접 풀 수 없음 — 「Flutter·음성은 어떤 경로로도 lock을 **직접** 풀 수 없음」 ([설계서 §3.4](../../docs/2026-10-19-s3-s10-design-v0.1.md) 마지막 문단). 10/04 작성 당시 출처였던 `inbox/category/voice-interface.md`·`docs/final-demo-architecture.md`는 #80에서 아카이브됨

| 필요한 것 | 내용 |
|---|---|
| 인덕션 명령 | `FanCommand`와 같은 형태의 요청 topic (단계, 출처 `flutter`/`voice`) |
| 상태 | `induction_level` 추가 |
| 음성 해석 | 「켜」「올려」「내려」「꺼」 → 단계 |
| 계약 | JSON Schema·Dart DTO·예제 동시 수정, `schema_version` 상향 |

### 안전 규칙 (제안)

- **잠금 중에는 켜기·올리기 거부**, 화면에 거부 이유 표시
- 잠금 해제는 계속 터치·음성 불가
- **내리기·끄기는 항상 허용**
- 음성으로 **켜기**까지 허용할지 별도 결정 — TV 소리·옆 사람 말로 켜질 수 있으므로 켜기만 터치로 제한하는 안 포함
- 정책 판정은 `SafetyPolicy`에서 한 번만 구현 (Flutter·gateway에 중복 구현하지 않음)

### 단계 수 (합의 필요)

| | 3단 (약·중·강) | 9단 (실제 인덕션) |
|---|---|---|
| 음성 | 「강불로」처럼 직접 지정 가능 | 「화력 올려」 8번에 최대 |
| 시연 | 한 번에 변화가 크게 보임 | 변화가 작음 |
| 현실감 | 낮음 | 높음 |

## 5. 태블릿 쿡탑 (보류)

같은 LAN의 태블릿 브라우저로 Flutter 웹(기존 MQTT WebSocket 9001 사용)을 띄우는 안. 소프트웨어만으로 가능하지만 **시연에 ATLAS 외 기기를 써도 되는지** 확인 전까지 보류합니다. 쓰게 되면 오프라인 빌드(렌더링 엔진·한글 글꼴을 외부에서 받지 않게)와 웹 파일 호스팅이 필요합니다 [추정 — 확인 방법: 태블릿 비행기 모드 + Wi-Fi만 켜고 접속].

## 6. 센서 측정에 미치는 영향

- 핫팩 없는 상태에서 `max − median` 11.9가 나온 원인은 디스플레이 1의 약 40°C 발열이었습니다 [실측 2026-09-26]. 디스플레이 1이 빠지면 **원인째로 사라지고, 열화상 「디스플레이 영역 제외」 안(안 C)도 불필요**해집니다.
- 대신 **LED를 최대 단계로 켠 상태에서 빈 상태(OFF) 기준을 다시 측정**해야 합니다.
- 아크릴은 열화상이 보는 장파장 적외선을 거의 통과시키지 않아 카메라는 LED가 아니라 아크릴 표면을 볼 것으로 예상합니다 [추정 — 확인 방법: LED 최대 점등 상태로 `mlx_watch.sh` 기록].
- 밝은 LED가 카메라(YOLO) 노출에 영향을 줄 수 있어 밝기 상한을 둡니다 [추정 — 확인 방법: 점등 상태에서 사람 인식 결과 비교].
