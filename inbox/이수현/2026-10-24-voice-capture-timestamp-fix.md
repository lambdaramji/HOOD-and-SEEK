## 관측한 실패

공식25 문항을 표시하기 전, 기존 고정 head `4f3b60e`의 실제 송신 기동이 `capture timestamp unavailable; publication stopped`로 중단됐다. SenseVoice 로딩·PulseAudio 입력 시작·원음 시간 원점 로그까지 있고 ASR/공식 문항 마커는0개다. 이를 공식25의 실패 시도나 집행 성적으로 세지 않는다. 재시도2·3은 systemd failed 상태를 inactive로 오인한 준비 도구의 조건에 걸렸다. 실패 원문과 원음·Core 수신 기록은 별도 보존했다.

## 수정 범위

GStreamer 버퍼 PTS는 SEGMENT를 통해 pipeline running-time으로 변환한 뒤 같은 시계와 비교한다. 기존 코드는 PTS를 직접 running-time으로 간주하고, 버퍼 시작뿐 아니라 끝까지 현재 시각보다 과거일 것을 요구했다. 버퍼 끝이 시계보다 앞서더라도 시작 시각이 알려진 경우에는 시작을 더 이른 신선도 기준으로 사용한다. [GStreamer 공식 동기화 문서](https://gstreamer.freedesktop.org/documentation/additional/design/synchronisation.html)

- 유효한 과거 버퍼: 기존처럼 끝 시각까지의 실제 age를 유지한다. 늦게 받은 버퍼를 새 음성으로 만들지 않는다.
- 끝이 앞서고 시작은 과거인 버퍼: 더 이른 시작 시각을 기준으로 잡는다. 송신 기한을 늦추지 않는다. 최초1회 진단 로그를 남긴다.
- 시작 시각·시계가 없거나 미래 시작/잘못된 duration이면 실제 송신 차단을 유지한다. 실패 로그에 PTS·running-time·clock·base·duration을 남긴다.
- 캡처 원음 sample0 원점도 SEGMENT 변환을 적용한다.
- 모델·VAD 확률/시작224ms/종료544ms·프리롤·음량·정규화·명령 규칙·5초 기한·Core 정책은 바꾸지 않는다.

`audio_pipeline`의 작은 계산 함수에 과거·정확한 경계·끝만 미래·미래 시작·시각 없음·빈/과대 duration·5초 넘은 지연 보존의 실행 검사를 추가했다. 패키지나 별도 설정은 추가하지 않았다.

## 재검증과 집계 방침

새 바이너리·모델 해시와 source head는 실제 공식25 시작 전에 #62에 다시 명시한다. 기존 부정36·실제 주변음300 기록은 `4f3b60e`에서 수행한 결과로 보존한다. 새 실행본의 결과로 이름을 바꾸거나 재측정했다고 하지 않는다. 명령 해석·VAD 내용이 동일함을 소스/회귀로 대조하고, 기존 주변음 PCM으로 새 실행본도 재생 검증한다.

새 실제 송신 기동·원문 시간·Core 수락까지 확인하기 전에는 기동 문제가 해결됐다고 판정하지 않는다. 공식25는 사용자의 수동 시작 뒤 새 구간으로 기록한다. 기존 실패 준비 구간과 섞지 않는다. 기한·시계 검사를 제거해 시험을 통과시키지 않는다.
