## 녹음본과 음향 유사도 비교 — 적용 검토

### 조사 결과

- [문서] 사용자가 제안한 방식은 **음성 템플릿 매칭 / Query-by-Example**에 해당한다. 새 음성과 등록 음성의 시간별 음향 특징을 비교해 후보를 찾을 수 있다. [ISCA 음향 템플릿 연구](https://www.isca-archive.org/interspeech_2011/muscariello11_interspeech.html)는 MFCC 등 특징과 DTW를 사용한다. ASR 출력의 문자열 치환과 다른 접근이다.
- [문서] **MFCC**는 짧은 음성 구간의 주파수 분포를 요약한 특징이다. **DTW**는 말하기 속도가 달라 늘어나거나 짧아진 구간을 맞춰 비교한다. 원시 WAV 샘플끼리 직접 뺄셈하거나 문장 전체를 고정 길이로 압축하는 방식으로 시작하지 않는다. 근거: [MFCC API](https://librosa.org/doc/0.11.0/generated/librosa.feature.mfcc.html), [DTW API](https://librosa.org/doc/0.11.0/generated/librosa.sequence.dtw.html).
- [문서] [2024 Multi-Sample DTW 연구](https://arxiv.org/abs/2404.14903)는 한 명령의 여러 등록 음성을 다루며 등록 수가 늘어날 때 계산량도 문제임을 설명한다. 한 녹음을 정답 패턴 전체로 취급하지 않는 원칙을 참고한다. 해당 연구의 결과를 한국어 HOOD-SEEK 정확도나 Pi5 지연으로 환산하지 않는다.
- [문서] [openWakeWord custom verifier](https://github.com/dscripka/openWakeWord/blob/main/docs/custom_verifier_models.md)는 기본 감지기 위에 특정 화자·환경의 양성/음성 예제로 학습한 작은 검증기를 붙인다. “공통 감지→사용 환경에 맞춘 추가 거부”라는 원칙이 참고된다. 단순 DTW 구현과 같은 제품은 아니다. [공식 README](https://github.com/dscripka/openWakeWord)는 영어 지원과 C++ 구현 제약을 명시하므로 한국어 ATLAS용으로 바로 채택하지 않는다.
