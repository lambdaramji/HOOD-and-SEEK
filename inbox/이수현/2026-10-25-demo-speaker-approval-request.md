## 원음 끝부터 판정까지

[실측] C의 원본 ReSpeaker PCM과 Pi5의 `capture_audio_origin.sample0_monotonic_ns`·`intent_monotonic_ns`를 사용했다. 같은 기기 monotonic 기준이라 Mac 수신 지연이나 기기 벽시계 날짜를 섞지 않았다. 원음 해시는 집계 JSON에 보존했다.

[실측/방법] 기존 보관 음원 검수 방법을 재사용하여500–4000Hz 대역,20ms 프레임·10ms hop, 후반 배경 중앙값+8dB의 연속 음성 에너지 꼬리를 주석했다.25개 곡선을 모두 시각 점검했고, 끝 경계 오차는−250/+100ms로 표시했다. **사람이 음소를 청취해 확정한 끝점은 아니다.** 파형·개별 끝점은 로컬 보존하며 공개 범위는 집계·방법·해시다.

|C 지연 지표|결과|
|---|---:|
|원음 신호 끝→intent 중앙값|1.162s|
|원음 신호 끝→intent p95|1.429s|
|원음 신호 끝→intent 최대|1.482s|

|별도 VAD 끝 추정값|0.945~1.342s|

[PM 결정] PM이 이 신호 기반 원음 끝 주석을 시연 근거로 수용했다. 이는 신호 기반 오차 범위 밖의 정확도나 일반 화자 성능 보장을 뜻하지 않는다. 근거: 집계 JSON `latency_suhyun`.

## 실행본과 부정 시험의 범위

[실측] A의 실행본은 `e9a395c478f1828024179c130969f0a546524640800cba0ee345be505a2d0684`, B·C는 `1c38613a7bf12c612c32a85b8c434863b2b4bf1f08e75f166beff4526ac8f1fc`다. 이번 커밋은 후자의 검증 소스에 해당하는 `페꺼·패꺼` 전체 팬 끄기 별칭, `푸도` 가전명 별칭, 명시적인 팬·인덕션 혼합 대상 차단과 경계 검사를 포함한다. 원격 source 기준은 `1fda3aa`이며 전체 소스 manifest 해시를 집계 JSON에 남긴다. 임의 화자 학습·모델·VAD·문턱·Core 정책 변경은 없다.

[실측] A의 새 현장 비명령36개와 실제 주변음150+150초에서 실행 후보0이었다. 비명령은 수음 상한 뒤 남은 문항만 이어서 완료했으며, 주변음 후반은 팬 켜짐·주변 소음·대화 있음으로 사용자 메모를 반영했다. 주변음에서 ASR7건이 모두DROP이었다. 시험 표시 전 연습·대화는 부정 문항 집계와 분리해 원본을 보존했다.

[실측/범위] B·C 실행본은 위 보관 비명령·주변음의 표시 구간4파일을 Pi5에서 다시 ASR하여56개 전사·실행 후보0·송신0을 확인했다. **같은 수정본으로 새 현장 비명령36·주변음300초를 녹음한 결과는 아니다.** PM은 보관 재전사를 최종 조건의 대체로 인정하지 않았으며 같은 실행본으로 새 현장 비명령36·실제 주변음300초를 요구했다. 근거: 집계 JSON `negative_evidence`.

[실측] Mac Release CTest7/7. Pi5 parser8206·HiLG 출력집계271·audio1569·TCP 형식60, 실패0. HiLG 출력 카운터 외에 추가 경계 반복 검사도 통과했다. 실제 TCP는 명시적 `--publish`일 때만 발행하며 기본은 계속 꺼짐이다. 새 commit CI는 별도 확인한다.

## 시연 대본과 자리 150 cm

[PM 결정/운영 기록] 화자는 **이수현**, 위치는 **C시험에서 ReSpeaker와150cm로 측정한 자리**다. 시작 전에 같은 자리를 확인하고 표시한다. 아래5문장만 시연 대본에 넣고 호출어와 명령을 한 번에 말한다. 인덕션 켜기·화력 증감 등 다른 표현은 이번 시연 대본에 넣지 않는다.
