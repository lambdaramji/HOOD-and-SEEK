## 결론

[실측] 기존 운영 실행본은 ReSpeaker를 지정해도 실제 Pulse 녹음 스트림이 USB 웹캠 마이크에 연결됐다. 운영 서비스 PID와 녹음 스트림의 프로세스 PID를 대조한 14개 표본이 모두 같았다. 관측 종료 뒤 서비스를 stop했다. 발행은 꺼져 있었고 원음은 저장하지 않았다.

[실측] 별도 후보에서 자기 녹음 스트림만 지정 source로 이동하고, 실제 연결을 확인한 뒤 PCM 처리를 시작하도록 수정했다. 정상·재기동, 입력을 강제로 바꾸면 중단, 없는 source에 대체 연결하지 않는 기기 검사를 통과했다. **운영 바이너리·유닛·env는 아직 교체하지 않았다.** 새 사람 발화 성공률이나 150 cm 성적을 측정한 결과는 아니다.

## 1. C 24/25와 부정 시험은 어느 마이크였나

| 대상 | 남은 증거 | 실제 장치 확정 여부 |
|---|---|---|
| C: 이수현 24/25 | ReSpeaker를 지정한 명령/env, `capture_ready source=...`, 원음·마커·Core 수락 대조 | **미확인** — 당시 실제 source-output→source 매핑 없음 |
| 새 비명령 36개 | 같은 ReSpeaker 지정과 시작 로그, 원음 무결성·39건 ASR·실행 후보 0 | **미확인** — 실제 연결을 증명하는 매핑 없음 |
| 새 주변음 401.68 s | 같은 ReSpeaker 지정과 시작 로그, 원음 무결성·26건 ASR·실행 후보 0 | **미확인** — 실제 연결을 증명하는 매핑 없음 |
| 이번 기존 운영본 재현 | 실제 운영 서비스/녹음 스트림 PID 대조와 Pulse source 매핑 | USB 웹캠 마이크 연결 확인 |
| 이번 수정 후보 | 실제 source-output index→지정 source와 `current-device` 대조 | 요청한 ReSpeaker 연결 확인 |

[코드/한계] 이전 `capture_ready`의 source는 명령행 문자열을 그대로 출력했다. `pulsesrc.device`를 설정하고 PLAYING을 요청했지만 실제 연결을 읽어 검증하지 않았다. 저장 원음의 16 kHz·mono는 GStreamer 변환 뒤 형식이므로 마이크 종류의 증거가 아니다. 음량이나 인식률로 과거 장치를 추측하지 않는다.

[문서] 따라서 과거 성공·오탐 집계는 관측 기록으로 보존하되 **ReSpeaker 성능으로 확정해서 표시하지 않는다**. 이번 웹캠 재현을 과거 모든 시험의 장치가 웹캠이었다는 결론으로 소급하지도 않는다. [기존 지정 화자 승인](https://github.com/lambdaramji/HOOD-SEEK/issues/62#issuecomment-6393921252)의 적용 범위와 새로운 검증은 PM에게 재검토 요청한다. #62를 임의로 재개·취소하지 않는다.

## 2. 관측된 입력 계층

[실측] PulseAudio에는 ReSpeaker와 USB 웹캠의 서로 다른 입력이 있지만 AudioManager는 논리 입력 `usb_mic` 하나를 노출했다. ReSpeaker를 지정한 기존 노드가 웹캠 입력으로 연결되는 현상을 확인했다. AudioManager 내부의 모든 선택 분기까지 조사한 것은 아니므로 특정 내부 코드 결함으로 단정하지 않는다.

[문서] 기본 입력 이름이나 AudioManager의 논리 장치 표시만으로 확인을 끝내지 않는다. 자기 GStreamer source-output의 실제 연결을 검사한다. 카메라·다른 사용자의 오디오를 끄거나 시스템 기본 입력을 바꾸는 우회는 하지 않는다.

## 3. 변경

- [코드] 기존 `pulsesrc`의 `source-output-index`를 얻고 기존 libpulse API로 **자기 스트림만** 요청한 source로 이동한다. 외부 셸 명령을 만들지 않는다.
- [코드] 실제 `current-device`가 요청과 일치하기 전에는 source pad에서 PCM을 버린다. 잘못된 입력을 원음 파일·VAD·ASR에 넣지 않는다.
- [코드] 시작 검증은 3초로 제한한다. 실패·없는 입력은 오류 종료하며 다른 마이크를 대체 사용하지 않는다. 검증 후 `capture_source_verified` → `capture_ready`를 남긴다.
- [코드] 처리 중 source가 바뀌면 해당 PCM을 버리고 기존 중단 플래그를 올린다. 기존 ASR 결과의 중단 검사와 캡처 오류 종료를 재사용한다.
- [코드] Pulse 옵션 빌드에서 libpulse를 명시적으로 링크한다. ATLAS SDK/기기의 기존 PulseAudio 17.0을 재사용하며 새 패키지·서비스·제품 설정을 설치하지 않는다.
- [문서] 수동 기동·기본 발행 끔, 모델·파서·별칭·문턱·VAD·Core/Flutter 계약과 송신 기한은 그대로다. 다른 담당자의 Flutter·Core·vision 코드와 공유 배포 문서는 수정하지 않는다.

## 5. 운영 적용 전 남은 것

[문서] 정인: 자기 스트림 이동·검증과 AudioManager 경계, 기동/재기동 결과를 검토한다. PM: 기존 C·부정 시험의 실제 마이크 미확인 사항과 새 실행본/입력 경로의 현장 재검증 범위를 결정한다. **새 바이너리이므로 기존 조건(a) 시험을 통과한 것으로 표시하지 않는다.** 사람 없는 상태에서 비명령 발화·150 cm 성공률을 대신 측정하지 않는다.

[문서] 이번 PR은 별도 시험본 준비이며 운영 유닛/바이너리 자동 교체·실제 발행·자동 기동을 하지 않는다. 적용 시 승인된 source 이름으로 수동 기동하고 실제 source 매핑을 확인한 뒤 승인된 범위에서만 발행한다. 입력이 바뀌어 오류/재시작을 반복하면 서비스를 stop하고 원인을 확인한다. 모델·문턱·별칭을 바꿔 문제를 가리지 않는다.

## Ponytail

[문서] GStreamer source 정보·pad probe, 기존 libpulse, 기존 종료/추론 중단 검사를 재사용했다. 새 추상화·서버·일반 화면 이벤트·제품 설정은 없다. 새 수동 검사 1개는 실제 라우팅 변경을 재현하기 위해, 이 보고서 1개는 과거 장치 귀속과 현재 재현/수정을 구분하기 위해 필요하다. 설정 문자열 비교만으로는 실제 입력을 고정할 수 없어 직접 자기 스트림을 이동한다. 안전·보정·시간 검증은 줄이지 않았다.
