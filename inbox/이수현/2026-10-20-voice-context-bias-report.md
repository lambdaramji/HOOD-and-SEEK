## 1. 비교 방법

- [문서] 같은 Whisper base 모델·한국어·CPU 4 threads·GPU 끔·audio context 기본 1500·초기 prompt 없음·36개 문장 후보를 사용했다. 음성은 한 번 인코딩하고 후보의 앞부분을 제공해 다음 토큰과 문장 종료 EOT의 조건부 점수를 구했다.
- [문서] 후보 점수는 토큰 logp의 평균에 ‘후드’ 포함 여부에 따른 가산을 더한다. 부정·질문·인용 문장도 ‘후드’가 있으면 같은 가산을 받는다. logp는 0에 가까울수록 높으며, 이 값은 명령 정답 확률이 아니다.
- [문서] 후보는 지원 문장 8·기존 거부/제외 8·추가 부정/질문 4·후드 없는 대립 8·푸드 대립 8, 합계 36개다. 지원 8개는 풍량 1/2/3과 다른 실행 결과 5개를 구분한 기존 실험 라벨이며 원격 TCP v1 allowlist 범위 안이다. 인덕션 명령의 최종 실행 허가는 SafetyCore가 유지한다.
- [문서] 비교값 0/0.05/0.1/0.2/0.5는 새 결과를 보기 전에 고정했다. 수용 문턱 없이 1위 후보의 종류를 비교했으며 어떤 후보도 실제 기기에 전송하지 않았다. 후보 문장을 미리 제시하는 방식이므로 자유 전사 정확도로 해석하지 않는다.

## 5. 판정과 다음 순서

- [문서/판정] 고정 가산은 추가 학습 없이 시도할 가치가 있는 기준선이다. **0.5는 다음 검증의 고정 실험값이며 제품 채택값은 아니다.** 알려진 후보 중 1위를 고르는 구조에는 목록 밖 입력에도 어느 후보가 1위로 나오는 한계가 있다.
- [문서] 사용자가 다른 실제 화자의 Mac 녹음이 가능하다고 답해 같은 24문장·모델·VAD·점수식의 무가산 0과 가산 0.5를 녹음 전에 고정했다. 해당 첫 검증은 아래 jeongin 결과로 완료했다. 두 값을 이 자료에 맞춰 다시 고르지 않았다.
- [문서] 새 화자는 별도 ID·새 폴더·별도 검증용 세션으로 저장한다. 우선 화자당 1세션·1라운드 24개를 녹음하고 원음/처리본 청취 후 지원 일치와 부정·질문·인용·푸드·후드 없음의 잘못된 실행 후보를 따로 집계한다. 한 명을 추가하는 검사는 첫 일반화 점검이며 폭넓은 화자 독립성을 입증하지 않는다.
- [실측/문서] 기존 세션 녹음기를 재사용해 별도 검증용(`test`) 저장·24문장·1라운드 전용 페이지를 준비했다. 학습용 split과 추가 라운드 요청은 거부하며 기존 파일은 유지한다. 로컬 페이지 HTTP 200·잘못된 token HTTP 403·초기 세션 0·JavaScript 문법을 확인했고, 사용자가 버튼을 누르기 전 마이크에 접근하지 않았다. 이후 완료 응답을 받아 파일·청취·후보 순위를 확인했다. 실제 화자 정체를 자동 인증한 것은 아니다.
- [문서] 새 화자 검사와 향후 ReSpeaker의 새 실제 발화 검사를 분리한다. 그 결과로 고정 가산과 작은 학습형 재순위 모델의 비교 필요성을 판단한다. 학습이 필요하면 증강 전에 원본 단위로 학습·조정·평가를 분리하고, 이번 검증에 쓴 음원을 다시 독립 최종 테스트라고 부르지 않는다.
- [실측] 제품 코드·정책·계약·모델·SDK·패키지 변경, 학습·변환·배포·실제 기기 제어·SSH·커밋·Push는 수행하지 않았다.
