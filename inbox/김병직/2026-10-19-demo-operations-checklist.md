## 요약 — 가장 실수하기 쉬운 다섯 가지

1. **카메라에 사람이 조금이라도 보이면 「재실」이다.** 최근 2 s 안에 사람이 한 번이라도 보이면 즉시 재실, 30 s(`P_absent_s`) 동안 안 보여야 부재다 [문서 설계서 §3.4]. vision-node는 사람 점수 원값을 보내고, SafetyCore가 `P_person_score` 0.35 이상만 「보임」으로 센다 [문서 `profiles/default.json`, `safety_core/src/policy.cpp` presence 절]. 운영자·관객·촬영자는 물론 포스터·모니터·휴대폰 화면 속 사람도 이 점수를 넘을 수 있다 [추정 — 확인 방법: 3.5절 정리 전후로 3.4절 명령의 person 점수 비교]. 이러면 **M8·M9가 실패한다.** → 2장 시야 경계와 대기 위치.
2. **고양이 잠금은 「사람이 안 보인 시간」이 먼저다.** 새 Core(`c87f8308…` 이후, #168 D-060)는 사람이 `P_cat_absent_s`(10/27부터 **5.0 s**, D-065 — 그 전 4.4 s #174) 동안 안 보이면 고양이 감시를 시작하고, 감시 중 `cat_hit`이 `P_cat_hits`회 이어지면 잠근다. presence(30 s, `P_absent_s`)와는 따로 센다 [문서 설계서 §3.4, #168]. 그래서 인형이 이미 있으면 나간 뒤 약 6.5 s, 나간 뒤 5 s가 지나 넣으면 넣은 뒤 약 1.5 s다 [추정: 4.4 s 때 실측(2026-10-26 18:43 #67 ④, 19:42 #67 6414095393)에 5.0을 넣어 계산 — 확인: 정인 SIGHUP 뒤 M9]. 인형을 손으로 놓으면 손이 빠진 뒤부터 세니 **화면 밖에서 집게로 넣는다**(4장 방법 C). 옛 Core `f8164e74`(10/26 18:37 전)는 사람이 마지막으로 보인 뒤 30 s가 지나 부재가 돼야 셌다. 회차마다 7장 「Core 해시」 칸으로 어느 쪽인지 남긴다.
3. **잠금은 사람이 화면에 있어야 풀린다.** 고양이 잠금(M9)은 인형을 **박스 밖까지** 치우고 사람이 화면에 5 s, 위험 잠금(M10)은 위험 해소 10 s + 화면 「위험 확인」 + 재실이다 [문서 §3.4].
4. **Pi 5를 켜면 vision-node를 손으로 시작한다.** `hoodseek-vision-node`·`hoodseek-voice-node` 유닛 모두 `disabled`라 재부팅 뒤 자동으로 뜨지 않는다 [실측 2026-10-26 Pi 5 `systemctl is-enabled`, #67 정인 10/25 「재부팅 뒤 vision-node 수동 기동 필요」]. 3.2절 명령.
5. **측정(3.4절, `cat-check`류)과 서비스는 카메라를 동시에 쓸 수 없다.** 측정 전에 서비스를 멈추고, 끝나면 다시 시작해 `active`를 확인한다. 리허설·E2E 중에는 서비스를 멈추지 않는다.

## 3. 시작 전 점검 (매 리허설·시연, 시작 30분 전)

### 3.1 전원·케이블

- [ ] Pi 5는 전용 27 W 어댑터: 라벨 `HT-PD27W-KC`, 정격출력 「5.1V⎓5.0A, 9.0V⎓3.0A, 12.0V⎓2.25A, 15.0V⎓1.8A, 27.0W」 [실측 2026-10-19 라벨 사진]. PD 5 V 5 A 협상, 2분 부하 중 저전압 0 [실측 2026-10-19]
- [ ] LED 판은 별도 어댑터 `XSC-0502000SEKU`(DC 5V 2000mA), 펌웨어 밝기 76/255(≈30 %)·전류 상한 1500 mA, GND만 공통 [실측 2026-10-20 정정인 #48: 3단 + 잠금 링 600 s 이상 없음]. D-036 「≥5 A」에서 바뀌므로 **합의 필요**(#48에서 PM 요청)
- [ ] Pi 4 어댑터: 10/20 현재 `COK-2310`, 정격출력 「5.0Vdc/3,100mA」(USB-A 2구 합계라 다른 기기는 꽂지 않는다) [실측 2026-10-20 라벨 사진, 정정인]. 10분 부하에서 `in0_lcrit_alarm` 0·`dmesg` voltage 0줄로 합격 [실측 2026-10-21 정정인, #64 사전 점검 표]
- [ ] 카메라 USB는 Pi 5에 직접 꽂음(허브 없이). 마이크와 같은 허브면 대역이 겹칠 수 있다 [추정, `inbox/정정인/2026-09-25-wiring-guide.md` §8-D]
- [ ] Pi 4↔Pi 5 LAN 유선 연결. M13에서 뽑을 케이블에 표식
- [ ] 운영 PC → Pi 경로: `ip route get <Pi5>`로 본다. Tailscale `accept-routes`가 켜져 있으면 `dev tailscale0`, 곧 마스터 PC(`<마스터 PC>`, 수현 노트북, 항상 켜 둠)를 거쳐 간다 [실측 2026-10-23: Pi 5 ping 손실 0/5, 평균 44.7 ms·최대 150 ms, 마스터 PC까지는 중계 없이 직접 3 ms]. 마스터 PC가 켜져 있으면 그대로 쓴다(10/23 김병직 결정). 마스터 PC가 꺼졌거나 PC → Pi 접속이 끊기면 `sudo tailscale set --accept-routes=false`로 끄고 `dev wlo1`(직접 연결)을 확인한다. 10/21에는 이 경로로 쓰다 접속이 끊겼는데, 선 정리가 안 된 때라 원인을 하나로 정하지 못했다 [추정 — 확인 방법: 끊기면 그 자리에서 `ip route get <Pi5>`와 `tailscale ping <마스터 PC>` 결과를 같이 남긴다]. Pi 4 ↔ Pi 5 연결(L1·L2)은 이 경로와 무관하다
- [ ] 카메라 USB가 끊겼다 붙으면 `/dev/video0`이 `video1`로 바뀔 수 있다 [실측 2026-10-21: `xhci-hcd.1: WARN: buffer overrun event` → `usb 3-1: USB disconnect`, 다시 붙은 뒤 `video1`]. 시작 전 `ssh root@<Pi5> ls /dev/video*`에 `video0`이 있는지 확인. 없으면 카메라를 잡은 프로그램을 끝내고 다시 꽂는다
- [ ] Pi 5 액티브 쿨러가 돌아감

### 3.2 켜는 순서 (제안)

### 3.4 ROI 어긋남 확인 (카메라를 건드렸거나 의심될 때만, 3분)

조리면·박스 위치는 프레임 픽셀 좌표로 저장돼 있어서, 카메라가 조금만 밀려도 고양이 잠금(M9)의 ROI 겹침 계산이 틀어진다. (제안) 먼저 앱 카메라 카드에서 박스 테두리가 화면 끝 근처 평소 자리인지 본다. 의심되면 아래처럼 프레임을 찍어 비교한다.

```bash
# (Pi 5) 서비스를 멈추고 3프레임만 찍음 → 마지막 프레임과 점수 기록이 log/check에 남음
systemctl stop hoodseek-vision-node
cd /data/hoodseek && . ./vision-node.env && mkdir -p log/check && \
  LLVM_PROFILE_FILE=/dev/null ./bin/hoodseek_vision --camera /dev/video0 \
  --model /data/ecoai/assets/models/object_detection/yolox.tflite --threads 2 --rotate "$ROTATE" \
  --max-frames 3 --dump-dir log/check --dump-every 3 --output log/check/rec.jsonl

# (Pi 5) 프레임마다 사람·고양이 최고 점수 (null = 0.10 이상 검출 없음)
#        사람 점수가 P_person_score(0.50, 10/27 D-065 — 그 전 0.35) 이상이면 SafetyCore가 재실로 센다
grep -oE '"(person|cat)":(null|\{[^}]*\})' log/check/rec.jsonl

# (Pi 5) 서비스 다시 시작 → active
systemctl start hoodseek-vision-node; sleep 5; systemctl is-active hoodseek-vision-node
```

```bash
# (내 PC) 프레임을 가져와 기준 프레임과 나란히 띄움 (아무 키나 누르면 닫힘)
scp root@<Pi5>:/data/hoodseek/log/check/frame_000003.ppm ~/hoodseek-ref/check.ppm
python3 -c "import cv2; cv2.imshow('ref | now', cv2.hconcat([cv2.imread('$HOME/hoodseek-ref/frame_ref.ppm'), cv2.imread('$HOME/hoodseek-ref/check.ppm')])); cv2.waitKey(0)"
```

- 박스 테두리·LED 판 네 모서리가 기준 프레임과 같은 자리에 있으면 통과.
- 어긋났으면 카메라를 테이프 표식에 맞춰 되돌리고 다시 찍는다. 그래도 안 맞으면 ROI를 다시 만든다(`vision_node/tools/roi_click.py`) → 새 `roi.json`을 PR로 올리고 Pi 5에 복사 → `systemctl restart hoodseek-vision-node` → 해시를 #67에 남긴다.

### 3.6 Core 기록 받기 (회차 시작 전, 새로 10/26)

Pi 4 Core 로그는 RAM에 16 MB까지만 남는다(`/etc/systemd/journald.conf.d/journald-atlas.conf`: `Storage=volatile`, `RuntimeMaxUse=16M`). state 줄이 많아 가장 오래된 줄이 약 48분 전이었고, 재부팅하면 다 사라진다 [실측 2026-10-26 17:0x Pi 4, 가장 오래된 줄 16:13:32]. 실제로 10/26 15:40·16:04 M9 구간은 한 시간 뒤 이미 없었다. **회차를 시작하기 전에 PC로 실시간 받아 둔다.**

```bash
# (내 PC) 회차마다 파일 이름만 바꿔서. 끝나면 Ctrl+C
mkdir -p ~/hoodseek-e2e
ssh root@<Pi4> 'date +%s; journalctl -u hoodseek-safety-core -f -n 0 -o short-unix' \
  | grep --line-buffered -E '^[0-9]+$|\[state\]' > ~/hoodseek-e2e/e2e-1.log
```

- Pi 4 BusyBox `grep`에는 `--line-buffered`가 없어서 거르는 것은 PC 쪽에서 한다 [실측 2026-10-26].
- Pi 4 시계는 10/26 19:14에 정정인이 맞췄다(`Sat Oct 3 17:47:42` → `Mon Oct 26 19:14:22`, Core 재시작 없음) [#67 정인 10/26 19:14–19:28 배포 기록]. 그 뒤로는 기록의 시각을 그대로 쓴다 [실측 2026-10-26 19:41: 파일 첫 줄 `date +%s`가 PC와 같음]. Pi 4를 재부팅하면 `date`로 다시 보고, 틀리면 파일 첫 줄(`date +%s`)과 각 줄 앞 숫자(`-o short-unix`)의 차이를 PC 시각에 더해 맞춘다.
- 정인이 10/26 아침부터 Core 로그를 Mac으로 실시간 받고 있다. Wi-Fi가 끊기면 다시 붙어 마지막 줄부터 이어받고, 17:21 기준 약 8시간 45분 동안 20 s 넘게 빈 곳이 없었다. E2E도 이것으로 받는다 [정인 Slack 10/26 17:21]. 위 명령은 그 수집이 멈췄을 때나 혼자 시험할 때 쓴다.
- 로그 크기는 E2E 직전이라 10/26에는 그대로 둔다 [정인 Slack 10/26 17:21].

### 3.7 카메라 카드 영상 확인 (새로 10/26)

**M9 인형 투입 방법 (10/26 실측으로 C를 쓴다)**

- **방법 C (10/26 #70 회차)**: 사용자가 인형을 가지러 화면 밖으로 나간 뒤 들어오지 않고, **화면 밖에서 집게로** 인형을 조리면에 넣는다. 옛 Core `f8164e74`에서 사람이 마지막으로 보인 뒤 30 s에 부재, 그 1 s 뒤 잠겼다. 잠금 창과 `CAT_LOCK` 음성이 나왔다 [실측 2026-10-26 17:05, #70 M9 기록, 병직 현장 확인]. 새 Core(#168·#174)에서는 넣은 뒤 약 1.5 s에 잠겼다 [실측 2026-10-26 18:43, #67 ④].
- **방법 B (손으로 먼저 올려 두고 퇴장)**: 사람이 있을 때 인형을 올려 두면 잠기지 않는다(= 「고양이 하나로는 잠그지 않는다」 시연). 새 Core(#168·#174, 4.4 s 때)에서는 사람이 서 있는 20 s 동안 안 잠겼고, 나간 뒤 약 5.5 s에 잠겼다(기대 약 6 s, 스톱워치 7.5–8 s) [실측 2026-10-26 19:42–19:43, #67 6414095393]. 중간에 사람이 한 번이라도 잡히면 `P_cat_absent_s`(10/27부터 5.0 s)를 처음부터 다시 센다. 옛 Core `f8164e74`에서는 손이 빠진 뒤 30 s를 세서, 10/26 16:04 회차는 인형을 놓고 잠길 때까지 77 s였다 [실측 2026-10-26, #168 본문].
- **방법 A (줄·막대에 달아 내리기)**: 팔이 화면에 들어가지 않는다. 쓰지 않았다.
- 팔을 뻗어 놓는 방법은 피한다 [추정: 팔·손만 보여도 person으로 잡혀 부재가 풀릴 수 있음 — 확인 방법: 10장 #2].
- 인형은 **조리면 가운데에 웅크린 자세로, 얼굴이 카메라를 보게** 둔다. v3e에서 이 자세는 LED 1단을 켠 상태로 cat hit 30/30(0.865–0.919, 겹침 0.42–0.52, 옛 ROI `b3eda292` 기준)이었다 [실측 2026-10-25 #67 정인]. 반려동물 칸은 `cat`(15)+`dog`(16)이다 [문서 설계서 §5.2, PR #89].
- (지난 기록, 원래 모델) 몸을 세워 등·옆을 카메라에 보이면 `person` 0.83~0.87로 잡혀 재실이 됐다 [실측 2026-10-20]. v3e에서 같은 자세를 다시 재지는 않았다 [추정 — 확인 방법: 3.4절 명령으로 그 자세의 person 점수].

## 5. 실패했을 때 복구 순서

**원칙**: 사람·소품 → 케이블 → 서비스 상태 → 서비스 재시작 → 보드 재부팅 순으로 본다. 판정 결과나 기준값을 현장에서 손으로 바꾸지 않는다(`profiles/`는 남현지 담당, 10/26 22:00 기능 동결 뒤에는 버그 수정만 [문서 BRD §8.2, #163 PM 리뷰 「22:00 기능 동결」]).

| 증상 | 확인 순서 | 담당 |
|---|---|---|
| **A. 「부재」로 안 바뀜** (재실 고정) | ① 시야 안에 사람·사람 사진·켜진 화면이 있는지(가장 흔함) → 모두 치우거나 대기 위치로 ② 3.4절 명령으로 person 점수 확인 → 사람이 없는데 `P_person_score`(0.35) 이상이 나오면 그 물체를 치우거나 조명을 바꿈 ③ 계속되면 사례(점수·물체)를 #57에 남김(남현지) | 김병직 |
| **B. 「미상」이 계속되거나 비전이 안 들어옴** | ① Pi 5 `systemctl is-active hoodseek-vision-node` → `inactive`면 start (Pi 5가 재부팅됐는지 확인, 요약 4) ② `active`인데 `NRestarts`가 계속 늘면 증상 C ③ `NRestarts`가 그대로면 LAN 케이블·Pi 4 SafetyCore 동작(정정인)·env의 `CORE` 주소 확인 ④ Pi 4 SafetyCore 로그에 `profile 로드 실패`가 있는지(정정인) — 프로필이 없으면 vision이 들어와도 신선도가 항상 거짓이라 미상으로 남는다 [실측 2026-10-19 PC: #76 호스트 빌드, 프로필 없이 `vision.fresh=false`, 넣으면 `true`] ⑤ `systemctl restart hoodseek-vision-node` 뒤 10 s 지켜봄 | 김병직·정정인 |
| **C. vision-node가 계속 재시작** (`NRestarts` 증가) | ① 카메라 USB 다시 꽂기 → 저절로 복구 [실측 2026-10-23 10.1절: `video0`으로 돌아오고 서비스 자동 복구]. 다른 카메라 프로그램(`live_view.py` 등)이 켜져 있으면 먼저 끈다 ② `ls /dev/video0` ③ `journalctl -u hoodseek-vision-node -n 20 --no-pager` 마지막 줄 ④ `ROI was calibrated with a different --rotate`가 보이면 env `ROTATE`와 `roi.json`이 다른 것(일부러 시작을 거부함 [문서 `vision_node/src/main.cpp`]) → 설정 바로잡기 | 김병직 |
| **D. 고양이 잠금이 안 걸림** | ① 사람이 마지막으로 보인 지 5.0 s(`P_cat_absent_s`, 10/27 D-065 — 그 전 4.4 s, 새 Core. 옛 Core `f8164e74`는 30 s — 7장 Core 해시로 확인)가 지났는지 — 손·몸이 화면 끝에 걸리면 다시 센다(그 전에는 안 잠기는 게 정상) ② 인형이 박스(ROI) 안에, 4장 자세로 있는지 ③ 조명이 2장 기준과 같은지 ④ 3.4절로 cat 점수 확인 → 기준값보다 낮으면 그 회차는 M9 실패로 기록(값을 현장에서 바꾸지 않음) | 김병직 |
| **E. 고양이 잠금이 안 풀림** | 인형을 **박스 밖까지** 치웠는지, 사용자가 5 s 이상 화면 안에 있었는지 | 김병직 |
| **F. 위험 잠금이 안 풀림** | 위험이 10 s 이상 해소됐는지, 「위험 확인」을 눌렀는지, **풀리는 순간** 재실이었는지 | 남현지 |

### 10.1 카메라 USB 분리 시험 (F7, 사무실에서 5분 — 10/23 끝남)

카메라 USB를 손으로 뽑아야 해서 원격으로는 못 한다. `live_view.py` 같은 다른 카메라 프로그램은 모두 끈 상태에서 한다.

```bash
# (내 PC) Pi 5 접속
ssh root@<Pi5>

# (Pi 5) 서비스 시작 → active
systemctl start hoodseek-vision-node
sleep 5; systemctl is-active hoodseek-vision-node

# (Pi 5) 분리 전 기록: NRestarts 값과, index0이 ../../video0을 가리키는지 (index1 -> video1은 메타데이터 장치라 정상)
systemctl show hoodseek-vision-node -p NRestarts
ls -l /dev/v4l/by-id/

# (손) 카메라 USB를 뽑는다. 아래 명령으로 10초 기다린 뒤 같은 포트에 다시 꽂는다
sleep 10

# (Pi 5) 꽂고 나서 10초 뒤 확인
sleep 10
ls -l /dev/v4l/by-id/
systemctl is-active hoodseek-vision-node
systemctl show hoodseek-vision-node -p NRestarts
journalctl -u hoodseek-vision-node -n 5 --no-pager
```

| 결과 | 판정 | 다음 일 |
|---|---|---|
| `…-video-index0 -> ../../video0`, `active`, NRestarts가 늘었고 journal 마지막 줄에 `cannot open camera device`가 없음 | 통과 (저절로 복구) | F7 수정 안 함. 결과를 이 표 3번에 [실측]으로 적음 |
| `-> ../../video1`(또는 다른 번호), journal에 `cannot open camera device: /dev/video0`가 반복 | 실패 | 카메라를 다시 꽂아 `video0`으로 되돌린 뒤, 결과를 근거로 `deploy/` 코드 소유자(정정인·남현지)에게 서비스가 고정 경로(`/dev/v4l/by-id/…-video-index0`)로 카메라를 열게 하는 PR을 요청 |
