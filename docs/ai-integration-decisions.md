## 현재 결론

2026-10-19 설계 세션에서 PM이 역할 경계를 **Pi 4 = 안전 판정(SafetyCore), Pi 5 = 인지·HMI**로 확정했다(D-011, P-009 닫힘). 논리 경계(관측 노드는 판단하지 않는다, 단일 프레임이 장치 제어로 이어지지 않는다)는 그대로이고 **보드 매핑만 바뀌었다.** 전체 설계는 `docs/2026-10-19-s3-s10-design-v0.1.md`가 단일 기준이다.

아래 "이번 소프트웨어 반영" 절은 MQTT 세대(2026-08-30) 기록이며 S10 전환 PR에서 아카이브된다.

이번 소프트웨어 반영에서는 다음을 구현했다.

- `hoodseek/v1/pi4/cat/detection` MQTT topic과 JSON Schema v1
- 좌표, score, ROI 중첩률, 시간과 source 입력 검증
- Pi5가 직접 계산하는 연속 hit, 확인 시간창과 해제 cooldown
- 사용자 부재와 고양이 ROI 침범이 함께 확인될 때만 인덕션 잠금 후보 생성
- 고온·고농도·heartbeat fail-safe가 고양이 감지보다 먼저 평가되는 안전 우선순위
- 단위 테스트와 CI 계약 문법 검사

실제 카메라 캡처, 모델 로딩, Atlas `VisionService`, ECO.AI, TFLite, QNN, ROI 좌표와 인덕션 D-Bus/릴레이 연결은 구현 완료로 표시하지 않는다.
