# LG 제공 원문 검토 기록

- 작성일: 2026-09-02
- 갱신: 2026-09-20 (LG 2026-09-03 회신 반영)
- 상태: 검토 완료 · 구현 반영 대기
- 대상: LG가 제공한 ATLAS 개발 문서와 API 명세
- 관련 결정: [P-009](decision/P-009-pi4-pi5-role-reallocation.md), [P-010](decision/P-010-lg-source-custody.md), [P-001~P-007](ai-integration-decisions.md)

## 기록 원칙

LG 제공 원문을 검토했다. 원문의 재배포 권한과 기밀 표기가 불명확하므로 이 저장소에는 원문이나 긴 인용을 저장하지 않는다. `[문서]` 항목은 **원문 파일명과 절만** 적고, 아래에는 프로젝트에 적용할 결론만 기록한다.

각 결론의 상태는 다음과 같다.

- **적용**: 현재 작업 절차에 반영한다. 기존 활성 아키텍처의 책임·계약·안전 기준을 바꾸지는 않는다.
- **보류**: 연결한 P-/D-결정의 담당자 승인 또는 실측이 필요하다.
- **비적용**: 현재 프로젝트의 구현·아키텍처를 바꾸지 않는다.

외부 원문은 팀 합의를 대체하지 않는다. 구현에 영향을 주는 내용은 해당 P-/D-결정의 담당자가 승인한 뒤에만 활성 아키텍처 문서와 계약에 반영한다. 승인 전에는 이 문서의 결론을 구현 명세나 장치 제어 근거로 사용하지 않는다.

## 적용할 결론

### 1. 프로파일 문서는 보드 역할을 확정하지 않는다

- **표기:** [문서]
- **원문:** `guide-documents/01` PDF, `Profile hierarchy` 절
- **결론:** **보류** — Headless·Video 프로파일 구분은 P-009의 입력일 뿐, Pi4/Pi5의 안전 판단·비전 추론·broker·ESP32 연결을 결정하지 않는다. 현재의 `D-001` 책임 경계와 보드 매핑은 유지한다.
- **연결:** `P-009`, `D-001`
- **승인·확인 조건:** P-009 결정권자(현지·정인)가 Dart ARM64 독립 실행, ESP32 재배선, 카메라 장착 결과를 검토해 승인한다.

### 2. `VisionService`는 RPi5 후보 경로에서 제외한다

- **표기:** [문서]
- **원문:** `com.atlas.VisionService1` D-Bus 명세. LG 회신 2026-09-03 — RPi5 공식 미지원. 근거: [LG 회신 검토](../inbox/임재범/2026-09-03-lg-answer-review.md)
- **결론:** **비적용** — `VisionService1`을 목표 보드의 구현 후보로 두지 않는다. 8/30의 3.7~3.8 FPS는 이 미지원 경로의 참고값이며 P-009 승인 근거로 쓰지 않는다. 카메라 캡처·추론은 ECO.AI 직접 경로 등 권장 경로로 재측정한다.
- **연결:** `P-002`, `P-006`, `P-009`
- **승인·확인 조건:** 담당자가 권장 경로의 모델 artifact 경로·SHA-256·실행 로그를 남긴다.

### 3. 카메라 사용자 동의는 데모 점검 항목으로 적용한다

- **표기:** [문서]
- **원문:** `com.atlas.Camera1` D-Bus 명세, `permission` 절
- **결론:** **적용** — 실제 카메라 연결 전 점검표에 최초 동의 절차와 재시작 후 동작 확인을 포함한다. 이는 점검 절차만 추가하는 결론이며, 카메라 adapter 또는 권한 우회 구현을 승인하지 않는다.
- **연결:** `P-001`, `P-002`
- **승인·확인 조건:** 실제 카메라 제품명·장치 노드·해상도·권한 로그를 확보한 뒤 P-001/P-002 담당자가 결과를 승인한다. HD-3000 UVC 인식은 2026-09-20 실측됨.

### 4. SDK의 backend·모델 입출력 표는 모델 선택 근거로 쓰지 않는다

- **표기:** [문서]
- **원문:** `ECO.AI 레퍼런스` PDF, `백엔드 이름 표` 절 및 `모델 입출력 명세` 절
- **결론:** **비적용** — 문서에 열거된 backend 이름이나 예시 모델의 입출력 표를 HOOD&SEEK의 YOLO 모델, 클래스 라벨, tensor 후처리 또는 license 결론으로 복사하지 않는다. 계약은 계속 runtime 독립적으로 유지한다.
- **연결:** `D-002`, `D-005`, `P-006`, `P-007`
- **승인·확인 조건:** P-006 담당자가 같은 보드·데이터에서 후보 모델의 Recall·오탐·p95 지연·RSS·발열을 비교하고, P-007 담당자가 배포물의 라이선스 표기를 검토해 승인한다.

### 5. 문서의 대상 빌드와 실제 보드가 일치한다고 추정하지 않는다

- **표기:** [추정]
- **결론:** **보류** — 제공 명세의 빌드 대상·API 목록이 각 Pi 보드의 설치 이미지와 일치할 수 있으나, 문서만으로는 확정할 수 없다. 이 가정에 따라 서비스 의존성, D-Bus adapter 또는 보드 재배치를 구현하지 않는다.
- **연결:** `P-002`, `P-009`
- **확인 방법:** 각 보드에서 `/etc/os-release`와 설치 이미지 버전을 기록한다. `VisionService` introspect는 RPi5 지원 경로가 아니므로 권장 추론 경로의 실행 로그로 대체한다.

### 6. 현재 실측은 P-009의 선행 근거이며 결정은 아니다

- **표기:** [실측]
- **결론:** **보류** — Pi5에는 ECO.AI·YOLOX가 있고 Pi4 Headless에는 Vision AI가 없다. 2026-09-20에 HD-3000을 Pi5에 물려 V4L2 직접 캡처로 약 3.2 FPS person 감지를 확인했다. 이 관측만으로 안전 판단을 Pi4로 옮기지 않는다.
- **연결:** `P-009`, `D-001`
- **확인 방법:** P-009의 Dart ARM64 독립 실행·ESP32 시험 연결 결과와 함께 결정권자에게 제출한다.

## 반영 절차

1. 담당자는 위 확인 조건의 원시 로그와 결과를 해당 P-결정에 추가한다.
2. 결정권자는 P-결정 표 또는 D-결정으로 승인 사실을 남긴다.
3. 승인된 결론만 설계서(`docs/2026-10-19-s3-s10-design-v0.1.md`), 계약, 배포 설정 등 활성 아키텍처 문서에 반영한다.
4. 원문 자체는 재배포 권한이 명시되기 전까지 저장소에 추가하지 않는다. PR #16의 변환본 형태는 이 절차를 통과하지 못해 병합하지 않고 닫았다.
