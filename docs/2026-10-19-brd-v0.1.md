## 1. 비즈니스 목표

조리면 온도(열화상), 연기(미세먼지 입자), 사용자 재실(카메라), 반려동물 접근(카메라)을 한 보드에서 함께 판정해 후드 풍량을 올리고 인덕션 화력을 제한·차단하며, 음성과 터치로 제어하는 협력형 주방 안전 시스템 HOOD&SEEK을 만든다. 판정은 LG ATLAS 플랫폼 위의 Raspberry Pi 4 네이티브 서비스 한 곳에서만 하고, Pi 5는 비전·음성·화면을 맡으며, 팬과 인덕션 시뮬레이터는 ESP32가 상위 장치 고장 시에도 스스로 안전한 쪽으로 움직인다. 목표는 과열·연기·부재·반려동물 네 가지 위험을 단계별로 판정하는 안전 제어(Must)이고, 음성 제어와 Pi 4 전원 차단 복구는 안전 제어가 완성된 뒤 붙이는 Should 항목이다(D-24, D-29).

이 문서는 2026-10-19 기준 「개발 완료물 없음」 전제에서 다시 세운 계획(D-29)과 S3~S10 설계서 v0.1을 BRD 형식으로 옮긴 것이다.

### 1.1 문제 정의

가정 주방의 문제는 불이 나는 순간보다, 그 앞의 몇 분 동안 아무도 조리면을 보고 있지 않다는 데 있다. 개별 가전은 각자 편의 기능은 갖추고 있지만 서로의 상태를 모른다.

| 문제 | 현장에서 일어나는 일 | 결과 |
|---|---|---|
| 조리 중 부주의 화재가 매일 일어난다 | 2023~2025년 음식물 조리 중 부주의 화재는 3년간 7,500건, 하루 평균 6.8건이다(E1). 전체 화재의 가장 큰 원인은 부주의(46.8%)이다(E2) | 응급 출동·재산 피해가 반복된다 |
| 위험은 한 가지 신호로 판단되지 않는다 | 열만 높으면 정상 조리이고, 연기만 나면 뒤집기 중일 수 있다. 온도 상승 + 연기 + 사용자 부재가 함께 관측될 때 위험하다(개발계획서) | 단일 센서 경보는 오탐이 많아 사용자가 꺼 버린다 |
| 후드와 인덕션이 따로 논다 | 기존 스마트 후드·인덕션은 원격 제어·예약·음성 등 편의 기능 중심이고, 한쪽의 상태로 다른 쪽을 제어하지 않는다(개발계획서) | 연기가 나도 후드는 사람이 켜야 하고, 과열이어도 인덕션은 꺼지지 않는다 |
| 주방에 반려동물이 있다 | 국내 반려동물 양육 비율은 2024년 약 28.6%로 역대 최고다(E4). 고양이는 조리대 위로 올라간다 | 사용자가 없을 때 터치식 인덕션이 켜질 수 있다 |
| 안전 기능이 클라우드에 의존한다 | 인터넷이 끊기거나 서버가 느리면 경보가 늦는다. 가정 영상이 밖으로 나간다 | 정전·통신 장애 시 안전 기능이 먼저 죽는다 |

### 1.3 해결 방식

후드와 인덕션을 하나의 안전 시스템으로 묶고, 판정을 한 곳(Pi 4 SafetyCore)에서만 한다. 조리 한 회차는 아래 순서로 처리된다.

1. 사용자가 화면 터치 또는 "후드 인덕션 켜"로 인덕션을 켠다. SafetyCore는 잠금 없음 ∧ 위험 단계 ≤ 주의 ∧ 재실일 때만 켜기를 집행하고, 팬 최소 1단을 맞춘다.
2. 열화상(전체 프레임 1 Hz, 서브페이지 2 Hz)과 미세먼지(1 Hz)를 500 ms마다 판정해 정상→주의→경고→위험 단계를 정하고, 단계별 팬 최소 풍량을 올린다. 증기는 입자 크기로 연기와 구분해 오탐하지 않는다.
3. 카메라가 사용자를 30 s 이상 보지 못하면 부재로 바꾸고(20 s 안에 돌아오면 아무 일도 없다), 경고 이상이면 팬을 3단으로 올린다. 경고 단계에서는 인덕션 화력을 1단으로 내린다.
4. 부재 중 고양이가 조리면 구역에 연속 감지되면 인덕션을 잠그고 화력을 내린다(Q-S5-1 **B 확정** 2026-10-19: 즉시 0단). 고양이 감지 하나로는 잠그지 않는다.
5. 연기가 확인되거나 과열이면 위험 단계로 올려 팬 3단, 인덕션 0단 + 잠금을 집행하고 경고음을 재생한다.
6. 사용자가 돌아오고 자극이 사라지면 히스테리시스 시간 뒤 단계를 내리고, 위험 잠금은 **위험 해소 + 사용자 복귀 + 화면 "위험 확인"** 세 가지가 모두 있어야 풀린다. 화면·음성 단독으로는 잠금을 풀 수 없다.
7. Pi 4 전원이나 통신이 끊기면 3 s 안에 팬 ESP32는 3단, 쿡탑 ESP32는 OFF로 스스로 전환한다.

사용자는 음성으로 후드 강풍·중풍·약풍·팬 꺼, 인덕션 꺼(필수 5종) + 인덕션 켜·화력 올려·내려(선택 3종)를 말하고, 같은 명령을 화면 버튼으로도 낼 수 있다. 모든 요청은 같은 허가 규칙을 통과해야 집행된다.

### 1.4 가치

이 시스템의 가치는 사용자가 조리면을 보고 있지 않은 순간에도 가전들이 서로의 상태를 보고 먼저 움직이는 데 있다. 판단은 집 안 보드에서 끝나고, 영상과 음성은 밖으로 나가지 않는다.

| 구분 | 기존 방식 | 이 프로젝트 |
|---|---|---|
| 후드 풍량 | 사용자가 손으로 단수를 고름 | 온도·연기·부재 단계에 따른 최소 풍량을 자동 적용, 사용자는 그 위로만 조절 |
| 과열·연기 | 인덕션 자체 과열 보호만 작동, 후드는 무관 | 팬 3단 + 인덕션 차단 + 경고음을 한 번에 집행 |
| 자리 비움 | 감지 안 됨 | 카메라로 부재를 판정해 같은 온도에서도 더 보수적으로 대응 |
| 반려동물 | 차일드록 버튼을 사람이 눌러야 함 | 부재 + 고양이 접근 연속 감지 시 자동 잠금, 복귀 시 자동 해제 |
| 음성 제어 | 클라우드 음성 비서 경유 | 기기 안 whisper.cpp, 인터넷 불필요, 안전 규칙이 음성보다 우선 |
| 고장 시 | 제어기가 멈추면 마지막 상태 유지 | ESP32가 3 s 안에 팬 최대·인덕션 OFF로 스스로 전환 |

| 이해관계자 | 얻는 가치 |
|---|---|
| 조리하는 사용자 | 조리 중 전화·택배로 자리를 비워도 가전이 먼저 대응한다. 손이 젖어도 말로 팬과 화력을 바꾼다 |
| 반려동물 가구 | 집을 비운 동안 인덕션이 엉뚱한 접촉으로 켜지지 않는다 |
| 가전 제조사 | ATLAS 네이티브 서비스 하나로 여러 가전을 묶는 협력 제어 참조 구조. 클라우드 없이 동작해 프라이버시 부담이 없다 |
| 평가위원 | 온디바이스 AI(YOLOX·whisper) + 로컬 판정 + 독립 fail-safe가 한 시연 안에서 일관되게 보인다 |

### 1.5 경제성

음식물 조리 중 부주의 화재는 하루 평균 6.8건 일어나고, 반려동물 가구는 세 가구 중 한 가구에 가깝다. 이 프로젝트는 그 중 사용자가 조리면을 보지 않는 구간을 겨냥한다.

| 근거 | 값 | 출처 |
|---|---|---|
| 음식물 조리 중 부주의 화재 | 2023~2025년 3년간 7,500건, 하루 평균 6.8건. 추석 연휴에는 하루 7.3건 | E1 |
| 화재 원인 1위 | 2023년 전체 화재 38,857건 중 부주의 18,185건(46.8%). 최근 10년 평균 50.1%. 공동주택 화재 4,868건(전년 대비 6.4% 증가) | E2 |
| 부주의 중 음식물 조리 비중 | 서울 2019년 부주의 화재 3,504건 중 음식물 조리 1,238건(35.3%), 담배 다음 2위. 주거시설이 전체 화재의 41.2% | E3 |
| 반려동물 양육 가구 | 2024년 약 28.6%(추정), 2010년 17.4%에서 14년간 11.2%p 증가 | E4 |
| 플랫폼 | LG ATLAS AI-native OS는 가전 내부에서 온디바이스 추론(ECO.AI)과 서비스 간 D-Bus 협력을 제공한다 | E5 |

추정(가정값)

- [A1] 조리 중 화재 중 "사용자 부재" 상태에서 발생한 비율은 공개 통계에 없다. 소방청 국가화재정보시스템의 발화 요인 세부 항목("음식물 조리 중 자리 비움")을 열람해 확인한다. 확인 전까지 보고서에 수치로 쓰지 않는다.

- [A3] 제품화 시 추가 원가는 열화상 센서·미세먼지 센서·카메라 모듈이며, 판정 로직은 기존 가전 SoC에 얹혀 쓸 수 있다는 것이 가정이다. 단가는 조사하지 않았다.

## 2. 범위

기능별 범위는 2.1, 제외 범위는 2.2에 적었다. 용어는 위험 단계를 "정상·주의·경고·위험·고장", 재실 축을 "재실·부재·미상", 잠금 축을 "미잠금·고양이 잠금·위험 잠금"으로 쓴다.

### 2.1 기본선과 확장 목표

| 기능 | 목표 | 포함 기능 | 등급 | 확장 목표 |

## 3. 고객 요구

사용자는 조리하는 사람 한 명이며, 조리 중에는 손과 시선이 자유롭지 않고 자리를 비울 때는 아무것도 조작할 수 없다. 그래서 지시는 말로, 확인은 한 화면으로, 위험 대응은 사람 없이 이뤄져야 한다.

### 3.1 사용자

| 사용자 | 하는 일 | 이 시스템에서 쓰는 기능 |
|---|---|---|
| 조리하는 사용자 | 인덕션을 켜고 조리하다가 전화·택배로 잠깐 자리를 비운다. 돌아와서 무슨 일이 있었는지 한 화면에서 알고 싶다 | 음성·터치 팬 제어, 인덕션 켜·꺼·화력, 상태·사유 표시, 경고음, 자동 복구 |
| 반려동물 가구 | 고양이가 조리대에 올라간다. 집을 비운 동안 인덕션이 켜지지 않기를 바란다 | 고양이 잠금, 복귀 시 자동 해제 |

이해관계자로는 평가위원(임베디드 AI 활용도, ATLAS 플랫폼 적합성, 시연 안정성), LG 담당자(플랫폼 질의 회신: PeripheralManager 권한, NTP), 가상 고객인 가전 제조사(제품 편입 가능성)가 있다.

## 4. 기능 요구사항

기능은 감지, 판정, 집행, 비전, 음성, HMI·시스템으로 나뉜다. 핵심 설계 원칙은 네 계층의 책임 분리다. L1 집행(ESP32)은 명령을 실행하고 독립 fail-safe를 가진다. L2 안전(Pi 4 SafetyCore)은 센서를 읽고 유일하게 판정한다. L3 인지(Pi 5 vision·voice)는 관측과 의도를 보고만 한다. L4 HMI(Flutter)는 상태를 표시하고 요청만 보낸다. Pi 5의 세 프로세스는 Pi 4의 TCP :7420 서버로 접속하고 한 줄 JSON으로 주고받는다. 노드·메시지·상태기계의 세부는 설계서가 정의하며 이 장은 요구사항만 적는다.

그림. 4계층 구성도 — 설계서 §1 Mermaid 도식을 개발완료보고서 ②에 그림으로 옮긴다.

### 4.1 감지

| ID | 요구사항 |
|---|---|
| TR-SENSE-01 | MLX90640을 `/dev/i2c-1`로 서브페이지 2 Hz(체스판 2장 = 전체 프레임 1 Hz, `docs/hardware-facts.md` §3) 읽어 32×24 프레임의 max, median, max−median 지표를 계산한다. 디스플레이 발열은 시야 밖에 둔다(D-18, D-28). |
| TR-SENSE-02 | SPS30을 I2C로 1 Hz 읽어 PM2.5와 입자 크기(tsize)를 얻고, 부팅 후 60 s 이동 중앙값을 기준선으로 잡아 정상 상태에서만 천천히 갱신한다. |

### 4.2 판정

| ID | 요구사항 |
|---|---|
| TR-POL-01 | 판정은 Pi 4 SafetyCore의 `Policy::tick()` 한 곳에서 500 ms 주기로 한다. Pi 5와 Flutter는 임계값 비교를 하지 않는다. |
| TR-POL-02 | 위험 축은 고장 → 절대 온도 위험 → (65 °C급 고온 ∧ 과한 연기) 위험 → 65 °C급 고온 또는 과한 연기 경고 → 지표 경고(강불) → 지표 주의(중불) → 정상(약불·대기) 순서로 첫 일치를 취한다. 이 순서가 안전 우선순위다(CLAUDE.md 불변식 ①, D-054). |
| TR-POL-03 | 과한 연기 = 팬 3단인 동안 SPS30 포화(PM2.5 > 2000) 샘플이 15개 연속, PM2.5 기준선 + 50 아래로 떨어지면 해제. 연기만으로는 차단하지 않고 65 °C급 고온과 함께일 때만 위험(D-054, #65 10/24 실측). 기준선 + 30 이상 연기는 「연기 있음」 표시(PM_WARN)만, 비포화 증기는 입자 크기(tsize ≥ 0.49)로 표시하지 않는다. |
| TR-POL-04 | 단계를 내릴 때는 아래 단계 조건이 5 s(위험→는 10 s) 연속 유지돼야 한다. |
| TR-POL-05 | 재실 축: person 관측 시 즉시 재실(복귀 ≤2 s), **30 s** 무관측 시 부재(R2·D-040 ①; 20 s 이탈은 경보 없음), vision 메시지 2 s 만료 시 미상. 미상은 팬 계산에서는 부재로, 고양이 잠금 후보에서는 부재로 취급하지 않는다. |

### 4.3 집행 (팬·쿡탑 ESP32)

| ID | 요구사항 |
|---|---|
| TR-ACT-01 | 팬 ESP32는 `FAN n`(0~3)을 받아 GPIO26 **100 Hz** PWM 듀티 {0,85,170,255}를 적용하고 `ACK FAN n`을 돌려준다. 0→1단일 때만 0.3 s 3단 듀티로 기동한다(킥스타트). 구동 회로는 IRLZ44N 로우사이드(25 kHz는 1·2단에서 멈춤 [실측 #64 L5], #100). |
| TR-ACT-02 | 쿡탑 ESP32는 `IND n`(0~3), `LOCK 0|1`, `STAT`을 받아 WS2812B 16×16에 화력·잠금·fail-safe를 표현하고 ACK를 돌려준다. 밝기는 30% 이하다. |
| TR-ACT-03 | Pi 4는 목표가 바뀌면 즉시 송신하고, 변화가 없어도 1 000 ms마다 현재 목표 명령을 재전송한다(재전송이 heartbeat). 판정 전이 → PWM 변화 ≤500 ms(R6·D-040 ⑥). |
| TR-ACT-04 | 두 ESP32 모두 3 000 ms 동안 유효 명령이 없으면 스스로 fail-safe로 간다: 팬 3단, 쿡탑 OFF + 잠금 표시. 부팅 시에도 fail-safe로 시작한다(D-21). |
| TR-ACT-05 | ESP32는 스스로 판단하지 않는다. 쿡탑 ESP32에는 물리 입력이 없고 Pi 4가 보낸 `IND n`·`LOCK x`만 적용한다(#55). |
| TR-ACT-06 | Pi 4는 2 s 안에 ACK가 없으면 `FAN_NOACK`/`IND_NOACK` 사유를 상태에 싣고, 쿡탑 무응답 시 켜기를 거부한다. |
| TR-ACT-07 | 연결은 Pi 4 보조 UART(uart3 GPIO4/5 팬 → `/dev/ttyAMA3`, uart5 GPIO12/13 쿡탑 → `/dev/ttyAMA5`, 115200 8N1)로 하고 콘솔 uart0은 유지한다(D-17 유지, [실측 2026-10-19 #44] overlay 동작·노드 생성 확인, 핀 루프백은 진행 중). 노드 권한이 `root:dialout`이므로 SafetyCore 실행 계정이 root가 아니면 `dialout` 그룹이 필요하다(#47). ESP32 쪽은 `Serial2`(GPIO16/17)를 쓰며 USB 칩(CH340/CP2102)은 PC 플래시에만 관여한다. 잘못된 명령은 상태를 바꾸지 않는다. |
| TR-ACT-08 | 두 ESP32 모두 하드웨어 워치독을 켠다. 펌웨어가 멈추면(예: LED 구동 루프) 리셋되고 부팅 시 fail-safe(팬 3단 / 쿡탑 OFF+잠금 표시)로 시작한다. fail-safe 타이머가 멈춘 채 마지막 단계에 고정되는 경로를 막기 위함(정정인 2026-10-19). LED 판 전원은 ESP32와 분리하고 GND만 공통(D-27). |

### 6.2 가정

- 손난로 45~65 °C로 max−median 지표가 주의·경고 경계(PR #40: 16·22)를 넘는다. 10/23 재실측으로 확인한다. → **확인(#65 G3, 10/22 측정)**: 단계 겹침 없음, 경계는 주의 13.4·경고 22.79·위험 30.4로 확정(D-044, PR #101).
- 인센스 연기는 tsize < 0.49 µm, 가습기 증기는 그 이상으로 구분된다(PR #40 실측 0 오탐). 시연 박스에서도 같다고 가정한다. (10/26부터 가습기 시험은 하지 않는다 — 위 NFR-02, D-057)
- YOLOX COCO 모델이 고양이 인형을 반려동물 칸(cat·dog)으로 검출한다. 10/20 1차 실측에서 정면 웅크린 자세는 `dog` 15/15(0.75~0.82), `cat` 0회라 칸에 `dog`를 더했다(PR #89, PM 결정 2026-10-20). 위치별 확인은 #65 Q8.
- whisper.cpp가 `atlas-dev`(clang 20, glibc) 환경에서 크로스 빌드되고 Pi 5에서 4 s 세그먼트를 3 s 안에 처리한다. 10/20 판정.
- ESP32는 GPIO UART(D-17 유지)로 연결하며 두 번째 보드(CP2102 또는 여분 ESP32)가 10/22 G2 전에 확보된다. 확보 안 되면 한 보드 통합 폴백(10장 E-1).
- ipk로 설치한 서비스가 재부팅 후 자동 기동되거나, 안 되면 systemd 유닛을 쓸 수 있다. → **확인 결과(10/19 실측·10/23 결정)**: 부팅 자동 기동은 안 됨. root `/data` systemd 유닛을 재부팅 뒤 수동 기동 1회(#46 결정 (4), TR-SYS-04).
- 사무실에 시연 박스와 보드가 있고 예비 Pi 4·Pi 5 세트로 개발기·통합기를 분리할 수 있다.

- 권한: PeripheralManager1은 `perm_peripheral` privileged 권한이 필요하다. LG는 10/21 회신에서 동적 서비스 방식(systemd 유닛 + 장치 보조 그룹)을 안내했고, 그 방식으로 root 없이 `/dev/i2c-1`·`/dev/ttyAMA3`·`/dev/ttyAMA5`를 한 프로세스에서 여는 것까지 실측했다(#46 10/21). 제출 범위는 검증된 root 실행·`/dev` 직접 접근을 유지한다(#46 결정 (3), D-18).
- 시연: 현장 실시간, 시간 제한 없음(S1-5). 실제 화염·연소 없이 손난로·인센스로 재현(가습기는 10/26에 뺌, D-057).
- 제출물 형식: 개발완료보고서 PDF 최대 20p(필수 7항목, 가산점 "임베디드 AI" 표기), 작품소개서 docx 2p 나눔명조 11pt + 사진 원본, 시연 영상 YouTube 8~12분 자막 M1~M11 순서, 소스코드 GitHub public.
- 확인 필요(10/19 사무실): 하드웨어 품목 상태, Pi 4·Pi 5 고정 IP, ESP32 USB 인식(Q-19), `/dev/ttyAMA*` 번호, 고양이 인형 검출, 재부팅 자동 기동, 9/20 Pi 5 디스플레이 문제 결과.
